- **`agents monitors` `--run` no longer records `ok` just because the agent
  exited 0 (PHNX-2842).** A fire's frozen `ok` was reconciled against the run's
  later status (RUSH-2690), but `completed` still counted as success — so a
  merge-on-green monitor whose agent ran, hunted the fleet, and never merged
  showed `ok` while the PR stayed OPEN. `run`/`routine` actions now take an
  optional `postcondition` (CLI: `--postcondition <cmd>`, YAML:
  `action.postcondition`) — a shell command, `{event}` interpolated, that must
  exit 0 after the run settles. `agents monitors runs`/`view` then show `no
  effect` (not `ok`) when it fails, and persist the result on the fire record.
  `--run` without a postcondition still records `ok` on `completed` and warns
  at add time. Source: `cli/src/lib/monitors/{state,config,engine}.ts`,
  `cli/src/commands/monitors.ts`.
