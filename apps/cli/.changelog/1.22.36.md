- **`agents sync <repo>` no longer strands a merged change behind unrelated local edits.** A dirty working tree used to fail the sync outright, so one modified `agents.yaml` or a session's scratch file froze that box's layer at whatever commit it was on — silently, with nothing reporting it. Measured 2026-08-10: a merged fix could not reach three of three boxes, each blocked by files the incoming commits never touched. Now a dirty tree fast-forwards instead of rebasing, but only when that is provably safe: no local commits ahead of upstream, and no incoming path colliding with a dirty one. Otherwise it still refuses, and the message names the colliding paths (or the local commits) instead of just "uncommitted changes". A clean tree still rebases exactly as before. The rule lives in one place (`dirtyTreeRefusal`) that **both** `syncRepoGit` and `pullRepo` call, so `agents sync <repo>` and the bare `agents sync` umbrella — which reaches the user repo and `.system` through `pullRepo` — cannot answer the same question differently. `--ff-only` is the safe primitive here — it cannot rewrite local commits, and git aborts rather than overwrite a modified file, so the path check is a second guard rather than the only one.

- **A unified `agents config` namespace replaces the scattered configuration surface.** The CLI previously spread run defaults (`agents defaults run`), model-tier overrides (`agents models tier`), interactive host preference (`agents devices configure` / `agents devices set-interactive`), and the default browser profile (`agents browser profiles set-default`) across unrelated command trees. The new `agents config` command exposes a single `agent@version` keyed grammar:
  - `agents config list` prints every persisted key/value.
  - `agents config get <key>` reads one value.
  - `agents config set <key> <value>` writes one value.
  - `agents config unset <key>` removes one value.
  Supported keys: `run.<agent@version>.model`, `run.<agent@version>.mode`, `run.<agent@version>.effort`, `run.<agent@version>.tier.<cheap|default|best|ultra>`, `interactive.host`, `browser.profile`, and `devices.<name>.max-agents` / `scheduler` / `daemon` / `watchdog` / `browser.remote-control` / `notes` / `browser.profile`. The `@version` component accepts `*` for version-wide defaults and `latest` for the newest installed version. `interactive.host` is a fleet-wide user-level preference stored in central `~/.agents/agents.yaml`; it is not a per-device key. Storage is unchanged — `agents config` is a facade over the existing `run.defaults`, `model.tiers`, `config.*`, device config, and meta defaults — so mixed-version machines and the fleet stay compatible without migration. The old commands still work but emit a deprecation warning pointing to `agents config`. Teams remain intentionally out of scope for persistent config because teams are temporary. Source: `apps/cli/src/commands/config.ts`, `apps/cli/src/lib/config-keys.ts`, `apps/cli/src/lib/run-defaults.ts`, `apps/cli/src/lib/model-tier-overrides.ts`, `apps/cli/src/commands/defaults.ts`, `apps/cli/src/commands/models.ts`, `apps/cli/src/commands/ssh.ts`, `apps/cli/src/commands/browser.ts`.

- **`agents devices config <name> --inherited` shows user-level config that applies to a device.** Device config views (`agents devices config`, alias for `configure`) only display device-scope keys by default. With `--inherited` they also render user-level keys such as `interactive.host` under a separate "Inherited from ~/.agents/agents.yaml" section, so operators can see fleet-wide settings in the per-device context without mistaking them for device-local values. Source: `apps/cli/src/commands/ssh.ts`, `apps/cli/src/lib/device-config.ts`.
