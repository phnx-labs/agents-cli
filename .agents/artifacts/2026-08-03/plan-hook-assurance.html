The safety layer can switch off
and nothing notices

The 22 hooks are what make an agent safe to leave running unattended. Two audit findings show the layer has no assurance: four hooks were dead for months without a single failure, and the three guards that prevent irreversible loss are the untested ones.

Finding 2 — the destructive guards are the untested ones

All 5 rule-owned guards have tests. These three do not:

UNTESTED  git-guard.sh             # reset --hard, force-push, stash, clean
UNTESTED  rm-guard.sh              # rm -rf on protected paths
UNTESTED  large-file-add-guard.sh  # git add of a >5 MiB file
why this is the factory risk model For a supervised agent these are annoyances. For a factory they are the whole risk model — an agent running unattended at 3am with a silently-disabled rm-guard is the failure that ends the experiment.

03Plan

1 — A registration-integrity test

New hooks/registration_test.sh. For every *.sh/*.py in hooks/, assert one of: it has a hooks: entry in ../agents.yaml; it is invoked by a script that does (the verify-delivery-chain.py case); or it is in an explicit INTENTIONALLY_UNREGISTERED allowlist with a one-line reason. Anything else fails.

This turns "someone dropped a registration in an unrelated commit" from an invisible event into a red test. Seed the allowlist with the one genuine case, 02-expand-prompt-skill-refs.py.

2 — Tests for the three destructive guards

Following the existing _test.sh shape. Each needs three cases:

  • blocks the bad input — rc=2, reason on stderr
  • allows the benign neighbour — rc=0 and empty stdout (a PreToolUse guard writing to stdout on the allow path injects into the prompt)
  • fails CLOSED with no JSON parser — the footer-guard precedent: a bare jq call with || cmd="" silently allowed the exact thing it existed to block

3 — One runner, wired as the pre-PR gate

hooks/run_tests.sh over every _test.sh in hooks/ and rules/subrules/*/, non-zero on any failure. Referenced from hooks/AGENTS.md.

04Deliberately out of scope

  • Per-harness scoping. agents: is dead — proven behaviorally: rm-guard declares [claude, codex, gemini] yet is installed in kimi, droid and antigravity homes. Fixing it is an agents-cli feature in a different repo.
  • Tests for the 7 other untested hooks. Worth doing, but none can cause irreversible loss — they inject context or expand text. The registration test already covers the "is it wired" half for all of them.

05Verification

the standard each test must meet A test that only passes against the fixed state proves nothing. Each must be shown to fail against the broken state first — the same bar applied to 02-expand-prompt-user-shortcuts_test.sh, which reported 5 passed, 1 failed against the pre-fix script before it was accepted.
  • Run registration_test.sh against git show 606db6e:agents.yaml in a scratch tree — it must FAIL, naming the three dropped hooks.
  • Break each guard's parser lookup to an unconditional allow; the fail-closed case must go red.
  • bash hooks/run_tests.sh green on this box and on workstation.
  • Each guard run with a benign payload produces empty stdout.
