- **MCP sync no longer writes nothing and calls it success (RUSH-2677).** `capabilities.mcp` is `true` for every harness, but the code behind it was four independent `switch (agentId)` chains with four different membership sets — a config-path resolver, a config writer, an installer, and a parser. A harness present in one and absent from another resolved a real path and then fell straight through the writer: no file, no error, `{ success: true }`. Antigravity was the visible case (`agents sync antigravity` reported MCP synced and wrote nothing, so `agents doctor` kept flagging it missing), and pi, muse and warp had writers the installer never called. They are now one table, `MCP_TARGETS` (`apps/cli/src/lib/mcp-registry.ts`), pinned to `capableAgents('mcp')` by a completeness test — so a newly added harness must declare a format, or declare with a stated reason that its format is not implemented. A harness in the second group (copilot, amp, kiro, goose — none has a schema verified against the installed CLI) now reports `cannot write MCP config: <agent>: <reason>` instead of a silent no-op. Three path bugs fell out of the consolidation, each verified against the harness itself: **antigravity** MCP goes to the shared `~/.gemini/config/mcp_config.json` agy actually reads, not the per-version `~/.gemini/antigravity-cli/` state dir, and its remote transport is keyed `serverUrl`, not `url`; **grok** MCP is `[mcp_servers.<name>]` in `~/.grok/config.toml`, so the resolver no longer answers `.grok/mcp.json` and the parser no longer reads that TOML as JSON; **kimi** is read back from the `.kimi-code/mcp.json` the installer writes rather than `.kimi-code/settings.json`, so a synced server stops reporting as missing. Claude's user-scope MCP path is `~/.claude.json`, where Claude reads `mcpServers`, not `.claude/settings.json`. Source: `apps/cli/src/lib/mcp-registry.ts`, `apps/cli/src/lib/mcp.ts`, `apps/cli/src/lib/agents.ts`.
