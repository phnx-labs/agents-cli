# Proposed standalone secrets contract

Status: proposal, not implemented. [Plan](proposal.html) · [Tasks](tasks.md) · [PHNX-3989](https://linear.app/getrush/issue/PHNX-3989).

- **DEP-1:** The standalone secrets executable and SDK MUST function without agents-cli, its home layout, fleet registry, feed, daemon, account catalog or device discovery. agents-cli MUST NOT package the extracted engine. The only agents-owned integration is a bounded process client plus its agent/fleet policy.
- **FMT-1:** A bundle is a `version: 1`, `name`, `vars` document. Each env key has exactly one `literal` or `source`. Source providers are `local`, `onepassword`, `aws-secrets-manager`, `env`, `file`, and explicit opt-in `exec` when required by imported bundles. Provider options form a discriminated schema. Exec uses executable plus argv, never a shell string; default deny. Unknown fields/providers/versions and duplicate keys MUST fail validation. Literal is non-sensitive configuration only.
- **FMT-2:** Source values MUST preserve bytes by default. Environment injection rejects binary, NUL and non-string JSON selections. Optional file newline trimming must be explicit; imported legacy file/exec refs record their previous trimming semantics. `onepassword.ref` is a native `op://` URI. AWS requires secretId and region, optional jsonPointer, and at most one versionId/versionStage. Without selector it resolves current SecretString; with jsonPointer it parses JSON and selects a string. Local references are logical item IDs, separate from machine-specific store choice.
- **CFG-1:** User connection/auth configuration MUST be separate from portable bundle declarations. Resolve explicit `--file` or named configured bundle; no implicit executable configuration discovery. Cyclic provider bootstrap MUST fail. Native login/standard credential chain supply provider auth.
- **RES-1:** Resolution is asynchronous and all-or-nothing. Validate requested subset and expiry before starting the child. Multiple bundles preserve explicit input order; later bundles override earlier ones, matching agents' current documented behavior. The agents client retains its wider precedence: profile, account, auto-share, resolved bundles, then explicit --env overrides; this is agents policy, not provider behavior. Cache identity includes provider auth identity, ref/version, requested keys and opaque scope; local cache lifetime cannot exceed grant or temporary credential lifetime. Mutable cloud refs are freshly resolved for each exec/SDK invocation; batching/deduplication is invocation-local only. A broker MUST NOT reuse AWSCURRENT or an unversioned 1Password field across invocations. Local locks evict cached grants.
- **CAP-1:** Provider capabilities are explicit: metadata/read and optional write/delete/rotation, interactive unlock and ciphertext sync. 1Password supports writable owned bundle items and read-only external field references through the official SDK; AWS is initially read-only. Neither emulates local biometric policy. Unsupported operations fail before side effects.
- **EXEC-1:** `secrets exec` resolves into child environment only, preserves argument boundaries and forwards exit/signal outcomes. It MUST NOT put resolved values in launcher stdout, errors, traces, argv or plaintext staging files. It MUST strip unlock/provider-bootstrap credentials from the child unless a particular credential was explicitly selected as an application variable; deny loader/interpreter overrides. An authorized child may itself print values; this is outside the launcher's confidentiality guarantee.
- **CTX-1:** Headless/agent contexts MUST NOT trigger interactive OS prompts. The package accepts interaction mode and opaque scope; it does not know harness names. Human unlock is deliberate. agents passes its policy-restricted scope and allowed bundle set; standalone automation defaults non-interactive.
- **RPC-1:** The private client protocol uses bounded request/response framing over inherited pipes, separate from child stdout. It carries protocol version, request id, operation, bundle/item, keys, expiry options, interaction and scope. Reply values appear only on that private channel. Operations cover metadata, resolution, raw-item CRUD, grant lifecycle and value-free events. Missing/unsupported executable versions fail before value resolution. Pipes/flags are not a security boundary against the same OS user.
- **REMOTE-1:** `exec --host target` selects the secret source and leaves the child local. SSH around `secrets exec` selects execution location. `import --host` pulls into the selected local destination backend; `export --host` pushes into the selected remote destination backend. Metadata and unlock/lock with --host operate on that endpoint. Reject ambiguous file/host combinations. No `--device`, Tailscale discovery, fleet alias lookup or publisher election exists in the neutral CLI. Pinned host keys, bounded subprocesses and no multiplexed credential transport are required. Remote maps MUST reject GIT_*, *_PROXY and *_BASE_URL in addition to loader/interpreter keys before any local child starts (preserve remote.ts:56-61). Old peers cannot silently ignore key/expiry restrictions.
- **SYNC-1:** SyncBackend transports encrypted envelopes only. It is separate from plaintext provider resolution. Cloud provider refs are not copied to a local store as an implicit cache. Managed ciphertext sync is optional and carries its own auth configuration.
- **OWN-1:** Standalone secrets owns exactly one broker lifecycle. agents daemon does not host or take over that broker. Device-role credentials, reserved auth-bundle rules, readiness publication and single-publisher election remain agents policy.
- **MIG-1:** Cutover inventories bundles, raw items, metadata, scopes and identifiers. Preserve native access identity; adopt existing encrypted paths or atomically import/read-back. Never silently choose another backend after an auth/decryption failure. Never auto-delete original credentials, dual-write, or promise rollback to stale encrypted state after new writes.
- **MAT-1:** Metadata and audit surfaces MUST remain value-free. Reveal/raw operations and optional MCP value delivery MUST be explicitly identified as materializing. Bundle reveal MUST refuse under SECRETS_CONTEXT=agent, existing recognized agent invocation markers, or a noninteractive terminal. The agents client sets the neutral context signal; standalone also detects existing markers without importing agents. Preserve only the existing narrow raw-item exception. These context markers are accidental-disclosure protection, not same-user authentication. Existing MCP returns a tool-result value; no claim that those values are hidden from the model is permitted. No automatic registration of that tool into model contexts.
- **DIST-1:** Repository phnx-labs/secrets-cli publishes the secrets executable through scripts/release.sh; CLI/SDK and signed, notarized native helper release independently. Require successful notarization, stapling, signature/identity and downloaded-artifact assessment on the helper train; ordinary CLI release reuses that artifact. Ordinary agents releases do not build helpers. Standalone CLI updates and agents protocol compatibility are tested as an installed pair; engines cannot be silently rebundled to hide installation failures.

- **STORE-1:** Select a named-bundle backend explicitly or through saved configuration; 1Password connections bind a specific account and vault ID. Never use ambient last-signed-in account selection. Backend flags do not override explicit manifest source providers. Owned bundle items map environment names to field IDs; external references do not confer mutation ownership. No implicit local copy or authentication fallback.
- **IO-1:** Both platforms support manifest reference import/export and encrypted value backups using the existing AES-GCM passphrase envelope and an explicit private-stdin or interactive backup-passphrase source. Preserve bytes and metadata, preflight conflicts and unsupported policies, require --replace for overwrite, and read back writes. No plaintext staging or exported bootstrap credentials/grants. Multi-bundle cloud restore reports per-bundle receipts and partial completion honestly. Hidden bundles participate in --all. Plaintext export obeys materialization guards.
- **UNLOCK-1:** Preserve macOS unlock, 7-day default TTL, expiry/until exclusivity, key/scope restrictions and durable persistence. Normal grants clear on sleep; durable grants survive sleep/reboot until expiry or explicit lock. No mandatory new master/keychain password. Linux validates existing persistent-store readiness and reports lack of synthetic grant/lock capabilities. Provider durability is capability-based; 1Password desktop/vendor expiry cannot be bypassed or replaced with local value caching.
- **NAME-1:** Accept ordinary names and __ordinary-name__ with nonempty body and total length <=49, without paths. Apply grammar to validation, parsers and every store enumerator. Default discovery excludes wrapped names, list --all includes them, and exact lookup remains authorized normally. Revocation, migration, backup and internal inventory always include hidden names.

## Completion oracle

An installed secrets CLI injects a canary with agents absent. The packed and installed agents CLI contains no extracted engine but its real run/browser/account/profile/SSH/share consumers still work through the client. Remote source and remote execution are demonstrated on different machines. Real backend rotation is observed on a subsequent invocation. Restart/update leaves one broker. These outcomes, not moving files or passing typecheck alone, define the extraction as complete.
