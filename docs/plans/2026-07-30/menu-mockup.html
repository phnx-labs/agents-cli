The four design rules

RULE 01 · reader-side

Prune orphan sentinels on read

Cross-check attention sentinels against the live session set. Unlink orphans found during the read. Kills the 1d / 2h / 1h ghost rows at the source.

RULE 02 · rendering

Collapse "ACTIVE · other" as a section header

When the "other" group is idle-only, render it as an interactive section header (not a row with a session glyph). Header carries the count; submenu carries the sessions.

RULE 03 · rendering

Group NEEDS YOU by (agent, repo); drop generic filler

Multiple waiters in one repo → one row + submenu. Rows with a specific Notification message stay inline. Drop the generic — Claude is waiting for your input tail entirely.

RULE 04 · rendering

Explicit truncation, never silent

Header count = visible glyphs + explicit "+N more" count. If the 3-cap hides idle rows, render + N more idle › with a submenu. "N running · M idle" both show when non-zero.

Row-glyph legend — the single answer to "running vs idle"

GlyphStateDefinition (pid alive assumed)
●Running Transcript mtime < 2 min. Agent is producing output right now.
◐Idle Transcript mtime ≥ 2 min AND no attention sentinel. Turn is complete — sitting at the prompt.
⚠Awaiting input Attention sentinel present. Notification hook fired — progress halted until you answer.
✕Closed (hidden) pid dead. Never rendered. Extending today's pidAlive guard to the attention path removes the ✕ rows from the BEFORE column.
