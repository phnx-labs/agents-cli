- **`agents harness` header is always derived from the name; `--label` on `agents harness fork` is removed (breaking).** `agents view` / `agents harness list` no longer read a stored `label:` field — the header is derived from the harness's `name` by splitting on `-`/`_` and casing each token through a curated vendor/brand table (`deepseek` → `DeepSeek`, `openai` → `OpenAI`, `xai` → `xAI`, `moonshotai` → `Moonshot AI`, …), falling back to capitalize-first-letter for anything unmatched — e.g. `deepseek-flash` reads as `DeepSeek Flash`. `--label` is dropped from `agents harness fork`; any script passing it now gets a commander "unknown option" error. Existing YAML with a `label:` key still parses (the field stays in the type, just unread). Two new lib primitives round out harness management: `editProfile` applies fork-style overrides in place (same name, preserving the source's real `forkedFrom` instead of self-referencing), and `renameProfile` renames the on-disk YAML and cascades the `forkedFrom` rewrite onto every child harness that pointed at the old name. Source: `apps/cli/src/lib/profiles.ts`, `apps/cli/src/commands/harness.ts`.
