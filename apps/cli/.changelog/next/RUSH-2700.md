- **`agents sync --yes` and the `--device all` fan-out no longer report a refused write as a clean sync (RUSH-2700).** RUSH-2677 made a declined resource visible, but only on two of the three surfaces that can carry one: `agents sync <agent>@all --json` and the umbrella payload still emitted a hardcoded `ok: true` and omitted `declined` entirely, and `refresh()` returned `void` so the umbrella never saw the decline in the first place. Since the fleet fan-out injects `--json` on each peer, a harness whose MCP config format is unimplemented (copilot, amp, kiro, goose) reported success fleet-wide while writing nothing — the exact silent-success class RUSH-2677 set out to remove. `refresh()` now returns the declines it collected and prints a `Not written:` block on the human path; the umbrella carries them; and both JSON emitters derive `ok` from whether anything was refused. Audited all fifteen `emitJson` sites in `commands/sync.ts`: three can carry a decline and all three now do — the rest are failure payloads, `nothing to sync`, dry runs, repo-git, or `launch`, none of which run a resource sync. Source: `apps/cli/src/lib/refresh.ts`, `apps/cli/src/lib/sync-umbrella.ts`, `apps/cli/src/commands/sync.ts`.
