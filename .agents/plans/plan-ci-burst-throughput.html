Reduce CI latency during concurrent PR bursts

The Free organization has 20 GitHub-hosted runner slots, while each agents-cli PR currently creates about ten jobs. Route checks by changed component, remove runner-only work, and retain the three-way CLI suite so bursts finish without multi-minute shard queues.

Purpose

Agents frequently open several pull requests within minutes. The repository's GitHub Free organization permits 20 concurrent GitHub-hosted jobs, but a routine PR currently starts about ten. Factory-only and documentation-only changes also run the complete CLI suite. The result is runner contention rather than useful validation.

Load-bearing decision: retain three CLI shards and remove unrelated jobs. A fourth shard can shorten one isolated PR, but under a 20-job account limit it increases queue time for the concurrent PR bursts this change targets.
