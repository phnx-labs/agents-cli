Purpose

artifacts --help lists twelve commands. An agent reading it has to weigh twelve verbs to pick the two it actually needs. Several are duplicates of each other, one is a byte-for-byte copy of another, and two are internal tools sitting in the front door.

Five complaints were raised. Three are real; two are about things that are already fine. Checking each against the source first, because the fix differs:

Complaint Verdict Evidence
doctor is redundant True, 100% cli.ts:264 is .action(() => runSetup({})) — the same function setup calls at cli.ts:63. Zero doctor-specific code.
compile and decompile are a redundant pair False compile is a Commander alias on render (cli.ts:129). decompile is unrelated: it regex-extracts a base64 blob render embedded in <script id="artifacts-source"> (render.ts:484-491). Not an inverse.
setup sets up nothing False It writes ~/.artifacts/config.json, and that file is read at runtime — render.ts:388 for fonts.dirs, share.ts:84-89 for the share endpoint.
Chromium is a dependency Already false playwright sits in optionalDependencies (package.json:29-31) and is dynamically imported (pdf.ts:28-33). Never installed unless PDF is requested.
estimate is internal and should be hidden True Called from exactly one place, cli.ts:115. No other command uses it.
One correction that shapes the plan: a browser cannot write a PDF file non-interactively. open file.html displays it; nothing makes Safari or Chrome save a PDF without a human pressing Cmd-P. So "PDF through the default browser" necessarily means the CLI stops emitting .pdf files — and /output depends on it emitting them.

Proposed Changes

Twelve visible commands become four, with three internals still callable but absent from help.

What changes when you run it

When you run Today After
artifacts render plan.md writes plan.html unchanged
artifacts render plan.md --open not a thing writes plan.html, opens it in your default browser
artifacts preview plan.md renders and opens gone — use render --open
artifacts render plan.md --format pdf writes a PDF gone — render is HTML-only
artifacts new plan --blank not a thing writes blank plan.template.md (what template did)
artifacts new design not a thing writes DESIGN.md (what init design did)
artifacts template plan writes plan.template.md gone — use new plan --blank
artifacts init design writes DESIGN.md gone — use new design
artifacts setup / doctor config write + prereq check gone
artifacts estimate f.md prints token comparison works, hidden from help
artifacts pdf f.md --out f.pdf writes a PDF works, hidden from help

Hiding, verified against the pin

The repo pins commander@12.1.0 (bun.lock:98). At that exact tag, lib/command.js has cmd._hidden = !!(opts.noHelp || opts.hidden) and lib/help.js filters visibleCommands on !cmd._hidden. There is no .hidden() instance method at this pin — that fluent setter landed in a later major, so reaching for it fails.

You suggested an _estimate spelling. Renaming outright would break README.md:173 and cli.test.ts:172, so each internal keeps its real name and gains the underscore as an alias — both work, neither shows in help:

program.command('estimate',  { hidden: true }).alias('_estimate')
program.command('decompile', { hidden: true }).alias('_decompile')
program.command('pdf',       { hidden: true }).alias('_pdf')

Where setup's two jobs go

setup does two unrelated things and its config is genuinely read, so each half needs a home.

Half Read at Destination
share.baseUrl and tokens share.ts:84-89 Already has writers — share setup and share join (cli.ts:245-256). Nothing to do.
fonts.dirs render.ts:388 Keep the read exactly as-is; drop the CLI writer. Zero code change.
Chromium readiness check setup.ts:28-36 Deleted. PDF already self-reports: pdf.ts:29-32 throws with the install command.

The alternative — threading render --fonts-dir through four signatures (cli.ts to compileArtifact to renderMarkdown/normalizeHtml to cssFromDesign) — carries one string one level deeper and loses configure-once. fonts.ts:37-41 already resolves project-relative fonts against cwd with no config at all, so fonts.dirs only matters for fonts outside the checkout: a rare, once-per-machine line in ~/.artifacts/config.json, documented in the README. No env var, per the standing convention that configuration belongs in real config.

Risks

The one rollout hazard. The deployed ExitPlanMode hook prints this as the command every agent should run (plan-html-reminder.sh:142):

echo "    artifacts render .agents/artifacts/\$DATE/plan-<slug>.md --format html"

Commander errors on unknown options, so the moment --format is gone, every agent running that line gets error: unknown option '--format' and the plan-presentation gate fails — including sessions already in flight with a cached hook. So render keeps accepting --format html for one version:

Invocation Behavior in 0.3.0
--format html Accepted, no-op, hidden from --help
--format pdf or html,pdf Errors: PDF moved to artifacts _pdf; render is HTML-only.
Either, in 0.4.0 Removed entirely, noted in CHANGELOG

This is a deprecation window with a named removal version, not a permanent compatibility branch. It also decouples the two changesets, so the CLI can ship before every skill copy catches up instead of requiring a fleet-wide flag day.

Pre-existing bug found while mapping. cli.ts:25-34 has two output-path helpers that disagree: defaultOutFor (used by render) writes HTML next to the source, while defaultHtmlOut (used only by pdf, cli.ts:218) always writes into .artifacts/. Unifying on defaultOutFor is a one-line fix that belongs in this pass, or the inconsistency gets frozen into a now-hidden command.

Open decision — how far to take PDF. This plan hides pdf rather than deleting it, which keeps /output working. Deleting it outright means dropping src/lib/pdf.ts (83 lines), pdf.test.ts, and the playwright optionalDep — but work/commands/output.md:70 must switch to HTML-only first, since that command's whole job is dropping a PDF in Downloads. Default if nothing is said: hide, don't delete.
