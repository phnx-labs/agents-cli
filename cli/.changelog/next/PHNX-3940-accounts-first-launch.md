- **`agents run` shows and addresses accounts, not installation labels (PHNX-3940).** The account picker (`agents run claude@`, or balanced with no verified usage) now lists one row per account — `name · email`, plan, headroom, and a state word (`live`, `unverified`, `rate-limited`, `logged out`, `reconnect needed`) with its fix — and states the harness release once above the rows (`Claude 2.1.263 · automatic updates on`, plus why the picker appeared). A row carries a version only when its home is pinned behind that release (`pinned 2.1.207`); two homes signed into one account fold into one row and the recorded connect home launches. Picking an account resolves its home through the same path `agents run claude#work` uses, then prints `[agents] account 'work' · claude` and `[agents] Claude 2.1.263`. Every launch line names the account the same way — `balanced picked work · muqsit@example.com`, `rate-limit failover armed: trp, personal` (one entry per account), headless `[agents] running claude#work`, `Resuming … · account work`. Labels survive only in diagnostics (`view --versions`, `inspect`, `models`, `status`, `update`, `teams`, `accounts --json`, the `Running:` argv) rendered as `2.1.221 → 2.1.263` through one formatter, never bare. Additive JSON: `run.launch` carries `releaseVersion` and `account`; `agents view --json` `accounts[]` rows carry `latestRelease` and `installations[].updatePolicy`; `sessions --json` / `sessions watch --json` rows carry `accountName` beside the `account` email; droid/cursor/antigravity session rows report the release they run instead of a stale label. Source: `cli/src/lib/accounting/rotate.ts` (`foldRunAccountRows`), `cli/src/commands/run-account-picker.ts`, `cli/src/commands/exec.ts`, `cli/src/lib/exec.ts` (`describeHarnessRelease`), `cli/src/lib/installations/resolve.ts`, `cli/src/lib/session/discover.ts`.
