- **`fleet.discovery` / `fleet.ignored` are device-scoped with a union-on-read view (PHNX-3315).**
  Every box used to rewrite one shared `fleet.discovery`/`fleet.ignored` map in the
  top-level `agents.yaml` (each dismissal stamped `ignoredOn:<host>`), so two boxes
  dismissing different peers produced guaranteed git line-conflicts on the next
  pull. Each box now records ONLY its own discovery decisions and dismissals in its
  tracked device doc (`devices/<host>/agents.yaml` `fleet:` block), and the
  effective fleet view is recomputed as a deterministic, order-independent UNION
  across every device doc at read time — `ignored` beats `approved` for a
  conflicting name, and the newest `ignoredAt` wins a shared dismissal — so every
  box computes the identical view and no box ever rewrites another's file. A
  fold-then-delete migration moves the existing central maps into the owning box's
  device doc before the central keys are dropped (the device-doc write lands before
  the central strip, so a crash re-folds idempotently). `agents devices
  register/ignore/unignore/ignored`, discovery reconcile, the sync pending-diff, and
  `agents fleet capture` all read the union. Source:
  `cli/src/lib/devices/{discovery-policy,registry,device-docs,config-migration}.ts`,
  `cli/src/commands/{ssh,fleet-capture}.ts`, `cli/src/lib/state.ts`.
- **Agent-host registrations are device-scoped (`deviceHosts`) with a merged read (PHNX-3315).**
  Locally-discovered SSH hosts and inline registrations landed in one shared
  `hosts:` map in the top-level `agents.yaml`, so every box that enrolled a host
  rewrote the fleet-shared file. Registrations now write this box's device doc
  `hosts:` block; the effective host directory is the cross-box union (newest
  `addedAt` wins a name collision), and `remove` only edits this box's own doc. A
  fold-then-delete migration relocates the existing central `hosts:` map into this
  box's device doc and drops the central key. Source:
  `cli/src/lib/hosts/{providers/local,registry,remote-os}.ts`,
  `cli/src/lib/devices/{device-docs,config-migration}.ts`, `cli/src/lib/state.ts`.
- **`scope:'device'` native accounts move off the shared file into the device doc (PHNX-3315).**
  `addNativeAccount` accepted `scope:'device'` but always wrote the central
  `accounts.native` map, so a per-box login (and its email / `identityKey` PII)
  landed in the git-tracked, fleet-synced `agents.yaml`. A native login is
  machine-local, so its home now follows its scope: a `scope:'device'` identity
  (and any binding that targets it) writes this box's device doc `accounts:` block,
  keeping its identity PII off the shared file; genuinely fleet-shared account
  `defaults` and `scope:'version'` identities stay central. Every account reader
  (`listNativeAccounts`, `findUnifiedAccount`, binding resolution, rename/remove)
  merges the fleet-shared central store with this box's device slice. A
  fold-then-delete migration relocates existing `scope:'device'` natives and their
  bindings out of central (forward-only; no history rewrite). Source:
  `cli/src/lib/account-registry.ts`, `cli/src/lib/devices/config-migration.ts`,
  `cli/src/lib/state.ts`.
