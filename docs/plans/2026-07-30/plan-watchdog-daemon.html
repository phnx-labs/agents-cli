AGENTS-CLI · design · WATCHDOG = COMPOSITION

The watchdog is glue —
not a subsystem

Everything the watchdog does already exists as a built-in: routines are the loop, agents sessions is the detector, sessions inject / answer-router is the delivery, a built-in workflow is the brains. So we don't build a watchdog — we compose one from primitives, delete the bespoke --nudge loop, sentinel, and hardcoded prompt, and keep only the two pieces that have no built-in: the cooldown ledger and the stuck-decision.

01What the watchdog really is

Six capabilities. Four are already built-ins the watchdog either reuses or should reuse; only two are genuinely its own. --nudge isn't a feature — it's just the dry-run-vs-inject toggle on top of the generic injectIntoTerminal.

CapabilityVerdictBuilt-in
Detect active sessions + statereusesgetActiveSessions() — same call agents sessions uses; activity: working/waiting_input/idle
Deliver a messagereusesagents sessions inject <id> <text> → injectIntoTerminal
The loopduplicates→ a routine (cron on the daemon scheduler)
Enable / disableduplicates→ routine enabled / pause / resume

"Is it stuck?" heuristicbespokenone — isLikelyTrulyBlocked (keep as a cheap pre-filter)

02The composition

One system routine on a sub-minute cron drives the whole thing. Detection and delivery are the same primitives the rest of the CLI uses; the decision is a built-in workflow. The daemon hosts nothing bespoke — it just fires the routine.

03Delivery accuracy — pick the right channel, add kitty

"Injection can happen in so many ways" — and there's already a built-in that picks the right one by session state: answer-router.ts. The watchdog should route through it instead of blind terminal injection. The mailbox is not universal (pull-based, Claude-only, needs a live tool-calling agent), so it's the fast path, not the fallback.

Session stateChannelWhy
Running, still tool-calling (Claude)mailboxdrained at next tool call — fast, in-context
Parked on a question, has a railkeystroke injectneeds keys, not context; any harness
Parked headless, no railrun --resumeno next tool call; universal /continue
Parked, no rail, interactiverefusedon't let it rot in the spool

kitty slots in cleanly kitty is already detected as a host (active.ts:622) but has no inject backend. Adding one is an InjectTarget variant + a resolve.ts case (like ghostty's, keyed on session.host === 'kitty') + a branch in the injectIntoTerminal switch. Unlike ghostty, kitty's RC socket makes it a first-class, split-precise rail — not a focus-steal.

04The brains — a built-in workflow, not a hardcoded prompt

The decision instructions must not be hardcoded strings, and they're not a "playbook" either. They're the prompt body of a built-in watchdog workflow that ships by default, is customizable through the existing workflow layering (project > user > system), and lets the user pick the harness/agent — because that's what routines and workflows already let you do.

Not this

  • Prompt hardcoded in watchdog.ts
  • Model pinned 'haiku' in a constant
  • A bespoke playbooks/watchdog.md concept
  • No way to change instructions per repo

This

  • Ships as .system/workflows/watchdog/
  • Instructions = the WORKFLOW.md body
  • Harness/model = frontmatter + routine agent
  • Customize by overriding the workflow (user/project)
the one open knob Cost vs accuracy of the default. The cheap deterministic isLikelyTrulyBlocked runs as a pre-filter gate every tick (no LLM). When it flags a candidate, the watchdog workflow makes the accurate call. Open question for you: is the workflow the default decider (accurate, spends tokens on flagged candidates), or opt-in (deterministic ships the nudge; workflow only when enabled)?

05The bespoke two + the fixes that come free

07Verification — real flow, not proxies

  • Routine is the loop: enable the routine, park a real agent mid-promise, confirm the daemon-fired routine injects Continue. into its tmux split — quote the watchdog.log event.
  • Channel accuracy: a live Claude → mailbox; a parked TUI on a question → keystroke; a headless parked run → run --resume; a no-rail interactive → refused (not rotting).
  • kitty: a stuck agent in a kitty window gets a split-precise kitty @ send-text into the right split — no focus steal, verified by looking at the window.
  • Customizable brains: override the watchdog workflow (different model/instructions) for a repo/user; confirm the routine's decider uses it; the harness/agent is user-selected.
  • No double-nudge: extension no longer injects; concurrent MCP-bridge nudge + routine tick serialize on the locked ledger — one nudge.
