02

The causal chain

Four independent design gaps compose. Any one of them alone would be survivable.

Gap 1+2 — why the credential vanishes

shims.ts:281-284 scopes CLAUDE_CONFIG_DIR to the selected version home, deliberately, "so switching versions also switches the live Claude account." usage.ts:1259-1267 then derives the Keychain service by hashing that directory: Claude Code-credentials-<sha256(configDir)[0:8]>. And shims.ts:1326-1328 carryForwardAuthFiles only acts on agents declaring authFiles — antigravity, kimi, droid. Claude is not one, asserted by its own test (shims.auth-carry.test.ts:309-315). shims.ts never touches the Keychain at all.

The unprovoked logouts

versions.ts:2254-2261: when the health check finds no runnable version it installs latest and calls setGlobalDefault. That runs unattended every 6 hours (daemon.ts:614-615). New version dir → new empty home → new Keychain scope. You get logged out by a background process at a time uncorrelated with anything you did.

Gap 3 — the sandbox has no credential to give

Routines run in a sandbox overlay HOME by default (runner.ts:612). Building it, generateClaudeConfig (sandbox.ts:174-251) writes only settings.json — no .credentials.json, no oauthAccount. HOME is replaced (sandbox.ts:74-76) and the env is stripped to an allowlist whose single credential entry is CLAUDE_CODE_OAUTH_TOKEN (sandbox.ts:50-55) — the token your daemon never loaded. 22 of your 27 zion routine YAMLs now carry sandbox: false as a workaround, which inherits the same problem plus the expiry the source itself names.

It is not only Claude — the same mechanism in three more CLIs

The fifth audit found the identical single-use refresh-token rotation failure outside Claude, which makes it a systemic pattern rather than a Claude quirk:

  • Codex, mac-mini — "Your refresh token has already been used to generate a new access token." code: refresh_token_reused, which broke every hourly OpenClaw cron. With a telling nuance on recurrence: "standalone codex CLI auth is healthy… openclaw's own codex auth is broken — it uses a separate codex auth inside the openclaw home." Same credential, two homes, one rotates the other out.
  • Droid, zion, still open — WorkOS token refresh failed permanently … {"error":"invalid_grant","error_description":"Refresh token already exchanged."}
  • Grok and Kimi are logged out on m1–m6 and mac-mini — Waiting for authorization... and No model configured. Run `kimi` and use /login. These keep no transcripts of their own, so their failures are recorded in the dispatching Claude session — which is why a naive search of ~/.grok and ~/.kimi-code finds nothing and reads as "clean." The audit caught and corrected that error in its own earlier pass.
  • 68 Claude Code-credentials-<hash> keychain slots exist; 22 of 73 host×agent×version slots are currently expired. That is the per-version scoping problem from Gap 1, measured directly.

03

Why you never found out

  • The daemon never logs a failed run. One failure line in a 1.9 MB log, a spawn ENOEXEC from May. daemon.ts:361-367 wraps only the spawn. No feed entry, no mailbox, no notification — lib/feed.ts is not imported by runner.ts, routines.ts, scheduler.ts, or daemon.ts.
  • agents routines run exits 0 on failure (commands/routines.ts:878-892), and --json returns ok: true regardless (:867-875).
  • The one visible signal reads the wrong machine. The Last Status column comes from getLatestRun → getJobRunsDir → the local archive only (routines.ts:769-772, 802). Proven divergence in both directions: zion shows security-sweep … failed while its real last run on yosemite-s0 completed with exit 0; and review-open-prs genuinely failed on yosemite-s0 at 16:00 today — invisible from zion.
  • The failure becomes the report, then the next prompt. extractAndSaveReport runs on the failure branch too (runner.ts:774) and takes the last assistant text unconditionally, never checking is_error (:1156-1199). 107 zion report.md files literally contain “Not logged in · Please run /login” as the routine's report — and that string is then substituted into the next run's prompt via {last_report} (routines.ts:712-723) with no status gate.
  • No retry, and catchup can't help. The only cascade is rate-limit-gated and foreground-only (runner.ts:744-748); the detached daemon path says so outright (:969-971). Catchup compares startedAt only and never reads status (overdue.ts:79-83) — a run that started and died counts as “ran”.
You already built the missing piece

What to fix, in order

0Rotate the three exposed Linear keys — then make retention a security control

67 files, two machines, 48 of them in trash that nothing reaps. Rotation is yours to do. The systemic fix is the reaper I argued for on disk-space grounds and should have argued for here: a retention policy on trash/ and versions/ bounds how long a leaked credential survives. Consider also a secret-scrub on transcript write — the agent's own output is the leak vector.

1Restart the daemon with the keychain unlocked

Today, one command. Your routines are failing right now for this reason. Then make it non-silent: if readDaemonClaudeOAuthToken() returns nothing, log an ERROR and notify rather than starting a daemon that will fail every job it launches.

2Detect auth failure — the agent already tells you

The runner receives "error":"authentication_failed" and "terminal_reason":"api_error" and discards both. Classify them next to detectRateLimit, mark the run failed:auth, and stop writing the login prompt into report.md and the next run's prompt. Smallest change with the largest blast radius.

3Auth preflight before dispatch

Add a gate to ensureHostReady — the remote agents fleet ping --local --json already returns exactly the rows needed (commands/ssh.ts:467-472), and ready.ts already makes an SSH round-trip. Fail loudly on revoked. Extend to teams dispatch and routines, and remove the !hostName skip at teams.ts:1437. This converts 1,742 silent failures into one actionable message.

4Alert on failure, and read the right machine's status

Wire feed.ts (or your Telegram path) into the failure branch, and make Last Status query the host the routine actually ran on rather than the local archive. You already hand-rolled this watchdog on mac-mini — promote it into the product.

5One Claude credential scope per account, not per version

Either stop scoping CLAUDE_CONFIG_DIR per version for the credential (keep per-version config, share one credential scope — the correct model), or add a Keychain carry beside carryForwardAuthFiles. And delete the latest auto-install branch at versions.ts:2254-2261 so a background heal can never re-point your default.

6Fix the teammate record write, then the placement

The zero-byte truncation on the read path invalidates cleanup, display, and the scheduler's load counter. Fixing it fixes three symptoms. Then add an interactive-device exclusion so 71.5% of teams stop landing on your laptop.

7Surface the fleet commands, then the latency work

devices/ssh/hosts/apply in agents --help — a command with 0 uses in 1,256 transcripts is a discoverability bug, not a missing feature. Then §06: the two import fixes, the roots memoization, and the search intersection.
