Story

Across today's pass one principle keeps recurring, so name it: a rule earns the always-injected layer only if it is a reflex the agent must carry at all times. Everything else has a better home. The test for any rule is one question — does the agent need this in its head always, or only while doing a specific thing, and could a mechanism just do it instead of instructing?

  • Live state that changes (topology, load, device roles) belongs in an injection hook, refreshed every session, not frozen in prose.
  • A procedure you only need while doing X (dispatch how-to, the publish chain, the non-derivable traps) belongs in an on-demand skill loaded when you do X.
  • A mechanic that can just happen (fetch a clip, upgrade the fleet, propagate an account bundle) belongs in a CLI feature + hook, so no agent has to be told the steps.
  • A reflex, taste, or principle (F1–F5, "delegate across the fleet", "merged ≠ shipped") stays a rule — and only that.

Three findings ground this pass. /fleet:upgrade does not exist — the fleet-rollout half of release-to-fleet has to be built, not folded. Native Claude/OAuth logins cannot be copied host-to-host — that's a deliberate safety boundary (it rotates the token and logs the fleet out), so the account-sync idea is "propagate minted bundles," never "copy the logins." And clip-references is pure mechanics — the ideal thing to delete once a hook fetches the file.
