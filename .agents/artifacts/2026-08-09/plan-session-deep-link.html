Deep link from an artifact back into its session

Rendered plans carry a session in their provenance line, but there is no way back into that session. Make the session a clickable link that reopens the terminal — cursor in the input bar — via a custom agents:// URL scheme, resolving the owning host automatically (workstation to another box).

Purpose

A rendered plan's provenance line shows harness · agent · host · session · date, but the session value is plain text and dead. There is no path from the artifact back to the work. The goal: click a link in the artifact and land in the input bar of that session's terminal, even when the session lives on a different host than where the user sits, in Ghostty or any terminal.

Feasible — with one hard constraint. The artifact is a sandboxed browser document (your screenshot is file:///…), so the link cannot run a shell. It must hand off to the OS through a registered agents:// URL scheme whose handler runs agents sessions resume <id>. Everything past the id already exists.

Behavior — what happens when you click

  • First click on a machine: browser shows a one-time "Open agents?" prompt → Allow.
  • Terminal opens on the machine the user sits at (their real terminal), resumes interactively, cursor in the input bar.
  • Cross-host: if the session originated elsewhere, the resume transparently ssh -tts to the owning host and resumes there.
  • Dead session / gone transcript: the resume path already handles recover-vs-attach.
  • No handler (never-onboarded box, or a browser refusing the scheme): the artifact degrades to a "Copy resume command" affordance — never a dead button.

Proposed Changes

Two repos. Downstream of the session id, nothing new is needed — the resume engine, host resolution, and PTY-over-SSH already exist.

agents-cli — register the scheme + a resolver command

  • New agents open <url> (apps/cli/src/commands/open.ts): strictly parse agents://session/<uuid>[?host=<machine>], then call the existing dispatcher dispatchSessionLifecycleInPlace(id, host ? [host] : []). Pass id/host as argv, never interpolated into a shell.
  • New apps/cli/src/lib/deeplink/register.ts, idempotent, wired into fleet:onboard / agents sync, per-OS (macOS CFBundleURLTypes app + LSSetDefaultHandlerForURLScheme; Linux .desktop + xdg-mime; Windows registry). Precedent: apps/cli/src/lib/terminal/backends/vscodium-agent.ts.
  • agents doctor: check the handler is registered and resolves.

artifacts-cli — make the session part a link

  • In artifactMetadata() (src/lib/render.ts), set href: agents://session/<fullId> on the session part (the renderer already anchors any part with href; the hero is not scheme-sanitized).
  • Capture the full session id in detectArtifactContext() (src/lib/templates.ts:156-182, which truncates to 8 at :179) — short text stays, full id goes in the href.
  • Trusted-shell "Copy resume command" fallback (same mechanism as the theme toggle at src/lib/render.ts:248-269).

system repo

  • skills/plan-render/template.html:121-127: anchor the session: chip for parity.
  • skills/artifacts/references/authoring.md: document the scheme.

Public Interface

agents open 'agents://session/<id>?host=worker-s1'    # host is a routing hint only

# Emitted link in the artifact hero (renderer anchors any part with an href)
<a href="agents://session/<full-id>" rel="noopener">session: session-id</a>

Validation

# 1. Scheme resolves locally → terminal opens in the input bar
open 'agents://session/<a-real-local-session-id>'        # macOS
xdg-open 'agents://session/<id>'                         # Linux

# 3. Artifact carries the link
CLAUDE_SESSION_ID=<id> artifacts render plan.md --format html

# 5. Injection guard — must NOT create the file

Injection /tmp/pwned absent; non-UUID id rejected

Risks

  • Handler registration is the real work and is per-OS; ship idempotent, verify in agents doctor, and require agents on the GUI login PATH (note in onboard).
  • Scheme-permission prompt on first click — expected, one-time, acceptable.
  • URL parsing is an attack surface — accept only agents://session/<uuid>, reject everything else, pass as argv. Covered by a parser unit test.
  • Full session id in a shared artifact exposes an id that can resume the session; resume already requires being on / reaching the owning host over the authed fleet, so the id alone is not a remote-exec primitive, but note it for public agents share.
