- **Managed harnesses follow the latest release without replacing account homes (PHNX-3940).** Automatic updates are on by default and configurable with `updates.auto` and per-harness `updates.<harness>.auto`. Updates preserve existing home paths and identities, defer active installations, and stage and verify the executable before committing it. A concrete `--to` release pins an installation; `--to latest` resumes automatic updates. `agents update --check` previews without changing local state. Source: `cli/src/lib/installations/update.ts`, `cli/src/lib/daemon/harness-update-service.ts`, `cli/src/commands/update.ts`.
- **`agents accounts connect <harness> [name]` — stable accounts independent of releases (PHNX-3940).** A new account gets a fresh opaque installation label with its own isolated home, installs the current release into it (even when that release is already installed under another label), and drives the harness's native OAuth login there — the credential is never copied or fleet-synced. Reconnecting an existing account by name reuses that account's home and refuses to bind a different identity after login. Supported for the version-scoped, isolable harnesses (claude, codex first); others refuse with a clear reason instead of faking a flow. Source: `cli/src/lib/accounts/connect.ts`, `cli/src/commands/accounts.ts`.
- **`agents accounts logout` honors `@label` / `#account` selectors (PHNX-3940).** `agents accounts logout claude@<label>`, `claude#<account>`, or a bare native account name now signs out that exact home instead of always selecting the global default, and the sign-out runs under the harness's canonical config-dir env (CLAUDE_CONFIG_DIR / CODEX_HOME) rather than HOME alone. Source: `cli/src/commands/accounts.ts`.
- **Account-first read model for `agents accounts` / `view` (PHNX-3940).** `loadAccountCatalog()` / `buildNativeCatalog()` group installed homes by identity and derive a live connection state — a registered account whose homes are all signed out reads `reconnect-needed`, never a bare `connected` on the registry label alone — with the release/home kept as secondary diagnostics. Source: `cli/src/lib/account-catalog.ts`.
- **`installVersion` accepts an `installationLabel` independent of the release (PHNX-3940).** The npm install path can now stage the current release under an opaque label distinct from the version string, so many accounts can share one upstream `latest` under separate isolated homes; the frozen installation record keeps label and `releaseVersion` separate. Source: `cli/src/lib/installations/versions.ts`.
- **`agents accounts connect` allocates account homes safely — no cross-account overwrite (PHNX-3940 security fix).** Connect slots are now RANDOM opaque labels allocated to be disjoint from every home already owned by an account or currently signed in, so `connect work` after `work` was renamed `personal` can never land on and overwrite `personal`'s login. Retry-idempotency is provided by a device-scoped pending-connect map (cleared on success), not a name-derived slot. Connection state is now strict — a live credential in the home, not a bare metadata identity, so a stale/expired login reads `reconnect-needed`. A first connect selects the harness default only when none is configured, and an unnamed connect forces no name (it returns a hint to name the login). Source: `cli/src/lib/accounts/connect.ts`, `cli/src/lib/account-registry.ts`, `cli/src/lib/account-catalog.ts`, `cli/src/lib/state.ts`.
