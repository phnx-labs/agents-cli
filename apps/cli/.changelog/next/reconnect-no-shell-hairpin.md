- **The `--device`/`--host` auto-reconnect loop no longer hairpins into an unsupervised shell and retries forever.** When the SSH link to a `--device`/`--host` interactive run dropped and the peer's own `agents sessions focus <id> --local --attach-only` couldn't find a live tmux pane to reattach, its fallback opened an interactive login shell on the remote — appropriate for a human running `sessions go` by hand, but the automated reconnect loop can't supervise that shell, and its eventual close returned exit 255, indistinguishable from a fresh network drop. Since the reattach's `connected` flag is set as soon as the fast preflight probe succeeds, that stray 255 refilled the retry budget every cycle, so the loop reconnected, hairpinned into a new unrelated shell, watched it close, and repeated — forever printing "attempt 1/6" and leaving the terminal full of aborted-TTY escape codes. The reconnect loop now sets `AGENTS_FOCUS_NO_SHELL_FALLBACK=1` on the remote invocation, which makes the fallback refuse cleanly with a dedicated exit code instead of opening the shell, so a genuinely unreachable session now surfaces once and stops rather than looping. Source: `apps/cli/src/lib/hosts/reconnect.ts`, `apps/cli/src/commands/go.ts`.
