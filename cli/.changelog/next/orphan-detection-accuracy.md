- **A session with no observer no longer reports as healthy, and a working agent nobody is watching is now surfaced (RUSH-3125).** `classifyHostLink` decided a session's host link from two local signals — the owning IDE window's heartbeat and tmux's attached-client count — and when it had *neither*, it fell through to `connected`. That is the wrong default for a detector: the rows it silently blessed were exactly the ones with no observer (a bare terminal, a team spawn, a cloud task, or any `--device` session whose pane lives on another machine, since every signal it reads is local). It now returns a new `unknown` link, which says the question is open rather than answering it. `connected` is returned only on positive evidence — a counted client or a republishing window. Separately, a `no-client` link could only promote a session that was *already* `idle` or `input_required`, so a **running** agent whose client had gone kept reading `running` — the most expensive case to miss, since it keeps consuming tokens with nobody reading the result. A running session with no client is now `orphaned` **when its context is `terminal`**, i.e. it was launched into a window a human was meant to watch; `headless` and `teams` runs are unchanged, because having no client is their design and flagging them is the over-reporting that makes the word worthless. A deliberate `agents sessions detach` is still excluded first, `tmuxClients === 0` is still authoritative, and a merely `unknown` link no longer clears a derived `attached` presence — only a positive loss signal does. Source: `cli/src/lib/session/host-link.ts`, `cli/src/lib/session/active.ts`.
