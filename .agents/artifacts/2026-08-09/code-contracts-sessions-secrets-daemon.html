Surface map

Sessions

What it owns

agents sessions is the unified read and lifecycle layer over agent conversation transcripts. It discovers native harness formats, maintains the SQLite/FTS index, combines durable transcript metadata with live process state, reaches across the fleet, and provides the verbs that reopen, move, fork, or steer a session.

Command tree

Branch Commands
Find and inspect sessions [query], preview, tail, render, stats, insights
Live lifecycle focus, reconnect, attach, detach, resume, inject
Branch and move fork, migrate, migrations
Portability export, import
Index maintenance backfill, optimize
Organization bookmark
Compatibility go is the deprecated alias for focus --attach-only

Contracts code must preserve

Contract Invariant Canonical area
SES-1–7 Every supported harness has one canonical discovery/parser route. Malformed JSONL lines are skipped, unknown paths fail loud, normalization is cross-platform, and scans are bounded. lib/session/discover.ts, parse.ts, types.ts
SES-8–11 Every rendered row has a deterministic, non-LLM preview; terminal noise is cleaned and wide glyphs are never split. commands/sessions.ts, sessions-picker.ts, lib/session/digest.ts
SES-12–16 JSON emits the stable SessionMeta shape. cwd, process provenance, launch context, and row origin remain distinct axes. lib/session/types.ts, active.ts, provenance.ts
SES-17–18 Liveness checks defend against PID reuse. A proven live process never becomes vague unknown; dead and abandoned states remain honest. lib/session/active.ts, state.ts
Fleet resolution Exact IDs may stop on an exact hit; short prefixes fail closed when a selected peer is unavailable, avoiding ambiguous cross-device matches. sessions preview, fleet ID index
Confidentiality Exported bundles are redacted; raw transcripts never enter public PRs or public trackers. sessions export, sessions render

Boundary with the other two surfaces

  • Sessions identifies the requesting agent and session. Secret-access audit events must preserve that requesting identity.
  • The daemon may inspect live session state and steer it, but the UI may only render state or invoke the CLI; it may not become a second scheduler.
  • Detached agent processes are not owned disposable children of the daemon. A daemon takeover must leave them alive, and the successor reconciles them from durable state.

Secrets

What it owns

agents secrets stores named bundles, resolves their values through platform backends, applies prompt policy, injects values into a child process, records value-free access events, and synchronizes explicitly sealed bundles across devices.

Branch Commands

Child injection exec; also consumed by agents run --secrets <bundle>
Prompt policy policy, unlock, lock, status
Broker control start, stop
Import/export import, export, import-keyring, openclaw-keychain
Fleet sync push, pull, remote-list

Audit activity; full event history lives under agents events --module secrets

Contracts code must preserve

Contract Invariant Canonical area
SEC-1–5 Plaintext never lands on disk. OS stores are primary; file fallback is AES-256-GCM; synced state is age-encrypted; metadata stays prompt-free. lib/secrets/index.ts, filestore.ts, vault.ts, bundles.ts
SEC-6–10 Every command is permanently on one side of the materialization boundary. Injection goes only to the child environment; printing plaintext requires an explicit materializing verb. commands/secrets.ts, lib/exec.ts
SEC-8a Values never enter process argv. Tmux launches source a mode-0600 env file and unlink it before exec. lib/exec.ts
SEC-11–14 Metadata scans never prompt. Bundle reads batch prompts. Headless and agent launches are broker-only and fail loud instead of raising surprise biometric sheets. lib/secrets/headless.ts, agent.ts, bundles.ts
SEC-15, SEC-26 Audit is value-free and has one canonical write path: emitSecretAudit, feeding the append-only event log and bounded usage read model exactly once. lib/secrets/audit.ts, usage-db.ts
SEC-27 A cancelled biometric read opens a five-minute negative memo so a poller cannot repeatedly raise Touch ID. lib/secrets/read-backoff.ts
SEC-28 Every access retains the requesting agent, session, parent session, PID, and caller provenance. secret audit provenance path

Boundary with the other two surfaces

  • The daemon hosts the macOS in-memory secrets broker. secrets start brings up that daemon; secrets stop locks bundles but deliberately leaves the daemon running.
  • agents run --secrets is an agent launch and therefore broker-only even when its terminal is interactive. It may not create its own biometric prompt.
  • Session identity flows into secret audit; secret values must never flow back into the session transcript, command line, or artifact.

Daemon

What it owns

agents daemon is the user-facing control and observation surface for the single long-lived runtime associated with one state directory. That runtime hosts the secrets broker and browser IPC, owns the routines scheduler, and drives device-local automation such as watchdog and cache-warm routines.

Command tree

Branch Commands
Lifecycle start, stop, restart, reload
Auto-start policy enable, disable
Observation status, services, logs, doctor

Contracts code must preserve

Contract Invariant Canonical area
SING-1–3 Every fleet-affecting capability has exactly one scheduler and executor. UI surfaces are thin wrappers and never own acting timers. lib/daemon.ts, lib/scheduler.ts, commands/daemon.ts
SING-4a daemon.enabled: false blocks every auto-start path but not an explicit daemon start; disabling does not stop a currently running daemon. lib/device-config.ts, ensureDaemonStarted
SING-5 Routines fire only through the daemon's PID-claimed JobScheduler. lib/scheduler.ts, lib/daemon.ts
SING-8–10 Multiple device daemons are legal. Shared-input work still needs one executor through an owner pin, atomic claim, or verified idempotency. routines device activation and claim paths
SING-11 Singularity is per state directory and uses last-wins takeover. The newcomer evicts the incumbent and waits for its resources to release before binding. claimDaemonInstance, reapStrayDaemons
SING-11a Detached routine/agent children survive daemon takeover; the successor adopts them through durable run records and PID ownership checks. runner.ts, monitorRunningJobs
SING-11b Every daemon-owned process class has a recovery/reaping layer across graceful death, takeover, SIGKILL, OOM, and reboot. daemon/browser/tunnel/keychain-helper reapers
SING-12–12a Stop is a verified postcondition, not “signal sent.” It checks PID registration, sockets, heartbeat, lifetime marker, and instance registry, reports survivors, and exits non-zero on residue. stopDaemon, stopResidueArtifacts
SING-14 Restart supervision is bounded by launchd/systemd throttles and the CLI auto-start circuit breaker. generateLaunchdPlist, generateSystemdUnit, isDaemonAutostartCircuitOpen

Cross-surface failure tests

Failure Required result
A headless agent asks for a locked keychain bundle Fail fast with the unlock instruction; no biometric sheet appears. The failed access stays attributable to the requesting session.
A daemon restarts while a detached routine is running Last-wins takeover replaces only the daemon. The child survives and the successor reconciles it from persisted run metadata.
Two devices evaluate shared queue work The owner pin or atomic claim produces one executor. Two daemons existing is not itself a defect.
A session row's transcript is malformed Skip only the bad line, retain the session when possible, and keep JSON/list rendering stable.
daemon stop leaves a broker or browser socket alive Report the survivor and exit non-zero; never print a false success.
A secret reaches tmux launch Only the temporary env-file path may appear in argv; the file is mode 0600 and unlinked before exec.
