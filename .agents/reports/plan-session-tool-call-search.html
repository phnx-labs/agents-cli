agents-cli · sessions subsystem · implementation plan

Index and query tool calls across devices

Agents need to find sessions where separate commands occurred, without reopening every transcript for each query. The design adds redacted call evidence to each device's SQLite cache, uses repeated clauses for distinct-call matching, and sends only compact matches over SSH.

01Problem and constraints

Current limitation

The session FTS row contains labels, topics, projects, and prompt text. It cannot prove that git merge happened in one call and gh returned CONFLICT in another call.

Required behavior

Return the session and matching call evidence quickly, keep transcript bodies on their origin device, preserve existing JSON contracts, and never process an unchanged transcript twice.

Matching rule. Terms inside one --query clause match one call. Repeated clauses are ANDed at the session level and assigned to distinct call rows.

02Command surface

# One exact session

03Distributed design

local dataSSH query/resultsdevice cache

Every device owns its transcript files and SQLite index. --fleet asks online compute devices to execute the same local-only query under the recursion guard. Raw transcripts and parser state do not cross SSH.

Bounded evidence. Inputs are redacted then capped at 16 KiB. Successful output is capped at 1 KiB; error text at 4 KiB. Base64-like blocks are replaced. --no-redact never disables index redaction.

05Complex Bash parsing

unbash@4.0.5 is a zero-dependency TypeScript parser compatible with the Bun-compiled CLI. The typed walker covers pipelines, AND/OR chains, control flow, functions, subshells, command/process substitutions, arithmetic expressions, and heredoc expansions. It reads lazy Word.parts explicitly.

Persisted

Static program basenames, redacted origin text, parser diagnostics, native call id, and structured metadata supplied by the harness.

Not inferred

Variable-dispatched executables or exit/status/error codes embedded in prose. Malformed Bash emits no program rows.
