The CLI turns Markdown with YAML frontmatter into self-contained HTML, paginated or poster PDFs, and optional shareable links. Provenance fields — project, repository, branch, harness, agent, human, host, session, date — auto-fill at render time.

02Recommendation

Yes — update the user-level plan-render skill to author Markdown and call artifacts render. Apply the same change to visualize so both skills share one compiler. Add the artifacts skill to the user repo so agents know the CLI conventions.

the takeaway The source of truth becomes Markdown + DESIGN.md; HTML and PDF are build outputs. This matches artifacts-cli's design and eliminates duplicated rendering logic.

04Trade-offs

Pros

  • Single reviewed compiler for HTML/PDF
  • Token-efficient Markdown source
  • Auto-filled provenance
  • artifacts check validation

Cons

  • Requires artifacts binary installed
  • No hand-written HTML fallback if missing
  • Existing templates need rewriting
caveat Environments without artifacts will fail rather than fall back to inline HTML. This is consistent with the artifacts skill's own contract, but it makes installation a hard prerequisite.
