- **`agents permissions list` and `export` now answer for all 13 harnesses, not 3 (RUSH-2676).** `applyPermissionsToVersion` writes permissions for claude, opencode, codex, cursor, antigravity, grok, goose, kimi, droid, copilot, kiro, openclaw and hermes, but the read side was a hand-written 3-arm switch: `readAgentPermissions` returned `null` for everything except claude/opencode/codex, `exportAgentPermissions` had the same shape, and `exportPermissionsFromPath` could only auto-detect `.claude`/`.opencode`/`.codex` path fragments. So permissions were installed for ten harnesses and then reported as absent for all ten — measured against the real write path, 13 written, 3 reported back. A new `PERMISSION_TARGETS` registry (`apps/cli/src/lib/permissions-registry.ts`) declares each harness's config path plus how to read it back into the canonical `PermissionSet`, mirroring `SUBAGENT_TARGETS`; a completeness test pins the key set to `capableAgents('allowlist')`, so a newly added allowlist harness cannot be written-but-unreadable. The registry also owns the canonical↔native tool vocabularies (`GROK_TOOL_BY_CANONICAL`, `KIRO_CAPABILITY_BY_TOOL`, and the rest), which `permissions.ts` now imports for the forward serializers, so the two directions cannot drift into disagreeing about what `fs_read` or `developer__shell` means. Every reverse projection is lossy in a way the harness's own format forces — Kiro collapses `Read`/`Grep`/`Glob` onto `fs_read`, Goose gates whole tools, Kimi expands one Bash arg-glob into two picomatch patterns — and each target names its own loss in a `lossyBecause` line rather than pretending the round trip is exact. `agents permissions list` renders the canonical allow/deny for the ten harnesses that had no renderer; claude, opencode and codex keep their native renderings (Codex records a sandbox mode, not a rule list, so its own fields say more than the blanket grants that mode widens into). Source: `apps/cli/src/lib/permissions-registry.ts`, `apps/cli/src/lib/permissions.ts`, `apps/cli/src/commands/permissions.ts`.
