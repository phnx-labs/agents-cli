# Evidence: harness sign-in mechanisms (fetched 2026-09-06)

Fetched by a research subagent from official docs. Columns: interactive login + storage · durable headless credential · multi-account · expiry signal.

| Harness | Interactive login & storage | Durable headless credential | Multi-account / isolation | Expiry signal | Sources |
|---|---|---|---|---|---|
| Claude Code | browser OAuth (paste-code fallback); macOS Keychain, else `~/.claude/.credentials.json` 0600 | `claude setup-token` → 1-year OAuth token via `CLAUDE_CODE_OAUTH_TOKEN`; Pro/Max/Team/Enterprise only; model requests only (no profile scope) | none native; `CLAUDE_CONFIG_DIR` isolates credentials and keys the Keychain entry per dir | "Login expired · Please run /login"; `/status` Login row; `claude auth status` JSON, exit 0/1 | https://code.claude.com/docs/en/authentication · /errors · /cli-reference |
| Codex CLI | browser ChatGPT OAuth; `codex login --device-auth`; `--with-api-key`; `~/.codex/auth.json` under `CODEX_HOME` or OS keyring (`cli_auth_credentials_store`) | API key (recommended for CI); or copy `auth.json` per runner (token bundle refreshes ~8 days; one file per machine, never shared) | none native; separate `CODEX_HOME`; `--profile` layers config not creds | `codex login status` exit 0 when logged in; 401 → refresh-and-retry, else `codex login` | https://learn.chatgpt.com/docs/auth · /auth/ci-cd-auth · /cli/reference |
| Grok CLI | browser to grok.com; `~/.grok/auth.json` 0600 under `GROK_HOME` | `grok login --device-auth` (RFC 8628); `XAI_API_KEY` fallback; session 30-day default lifetime, refreshed ~300s before expiry | single session; `grok login` switches; separate `GROK_HOME` isolates | re-prompts when refresh fails; no status command; `GROK_AUTH_EXPIRED=1` to external providers | https://github.com/xai-org/grok-build/.../02-authentication.md · https://docs.x.ai/build/settings/reference · /build/cli/headless-scripting |
| Kimi Code | `/login` device-code OAuth or platform API key; `~/.kimi-code/credentials/<name>.json` 0600, API keys in `config.toml` | `kimi login` device-code (headless prints URL+code); API key via config.toml / `KIMI_API_KEY` (legacy) | one OAuth account; providers are config; `KIMI_CODE_HOME` / `KIMI_SHARE_DIR` isolates | none documented; 401 "API Key appears to be invalid or may have expired" | https://www.kimi.com/code/docs/en/kimi-code-cli/... (getting-started, data-locations, kimi-command, providers) |
| Antigravity | OS keyring token profile, else browser; SSH paste-code; settings `~/.gemini/antigravity-cli/settings.json` | `GEMINI_API_KEY` (modelProvider gemini) for headless/CI; ADC via `AGY_ADC_AUTH=true`; headless uses cached creds after one interactive login | none documented; keyring-bound single profile | non-interactive unauthenticated run exits "authentication required"; "secret keyring is locked" | https://antigravity.google/docs/cli/install/ · /enterprise/ · /cli/headless/ · /cli/troubleshooting/ |
| OpenCode | `opencode auth login` per provider (browser for Claude Pro/Max, ChatGPT; device for Copilot); `~/.local/share/opencode/auth.json` | provider API keys via env; no OpenCode-native long-lived token | one credential per provider; no profiles; XDG data dir (unofficial) | `opencode auth list`; no expiry signal documented | https://opencode.ai/docs/providers/ · /cli/ · /troubleshooting/ |
| Factory Droid | browser sign-in; `/login` `/logout` `/account`; credential path undocumented | `FACTORY_API_KEY` (`fk-...`), service-account keys; no expiry stated | not documented | not documented | https://docs.factory.ai/cli/getting-started/quickstart · /droid-exec/overview · /enterprise/identity-and-access |
| Cursor CLI | `agent login` browser (`NO_OPEN_BROWSER=1` prints URL); storage path undocumented | `CURSOR_API_KEY` / `--api-key`, org-tied | not documented | `agent status` / `whoami`; "Not authenticated" | https://cursor.com/docs/cli/reference/authentication · /parameters · https://cursor.com/docs/api |

Cross-CLI: native multi-account support is **none**; isolation is always a config-dir env var. Machine-readable auth status exists only for Claude (`claude auth status`), Codex (`codex login status`), Cursor (`agent status`).
