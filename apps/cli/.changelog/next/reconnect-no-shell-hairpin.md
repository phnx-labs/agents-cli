- **The `--device`/`--host` auto-reconnect loop can no longer be defeated by a stray remote-origin exit code, and no longer hairpins into an unsupervised shell.** `reattachRemoteSession`'s `connected` flag is set as soon as the fast SSH preflight probe succeeds, before the actual reattach runs — so any remote-side path that happened to exit 255 for its own reasons (the peer's `agents sessions focus <id> --local --attach-only` opening an unsupervised login shell on a third machine when it found no live tmux pane, or a nested remote-tmux hop dropping) was indistinguishable from the SSH link itself dropping, refilled the retry budget every cycle, and looped forever — printing "attempt 1/6" on every cycle and leaving the terminal full of aborted-TTY escape codes. The remote invocation is now wrapped so that whatever exit code it decides on, a 255 is remapped to 254 before this process sees it: 255 is reserved exclusively for the local SSH transport's own connection-layer failure, regardless of which remote-side path produced the original code and regardless of the peer's `agents` version. The remote invocation also sets `AGENTS_FOCUS_NO_SHELL_FALLBACK=1`, which makes the peer's own fallback refuse cleanly with a dedicated exit code instead of opening the shell in the first place. Source: `apps/cli/src/lib/hosts/reconnect.ts`, `apps/cli/src/commands/go.ts`.
