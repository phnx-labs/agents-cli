4 Three calls I made — flag any you'd flip

A · Keep fleet status and devices separate?

They overlap (both show device/OS/load/mem). devices = "live capacity right now"; fleet status = "is the fleet healthy + in sync." I'd keep them separate but make fleet status cache-first so both are fast.

▸ recommend: keep separate, share the cache
B · Quiet-when-healthy, or always show every column?

Proposal hides auth ok / CLIs 9/9 on healthy rows and only marks exceptions. Some people like an explicit wall of green for reassurance.

▸ recommend: quiet by default, --verbose brings every column back
C · Add a live "sessions running" count per device?

You mentioned wanting "how many agents are running." That's a genuinely new signal (the current command never shows it) — would answer "where's my capacity actually being used."

▸ recommend: yes, but as a fast-follow ticket — needs a session-count source

5 The "offline" lie — and a unified transport

You SSH into yosemite-s1 every day, yet fleet status calls it offline. I probed it live tonight — it's fine. This is a whole class of bug, and it exposes that there's no real connection protocol underneath.

proof — yosemite-s1 is online right now
  • ssh yosemite-s1 → OK from yosemite-s1, tailscale 1.98.4 installed
  • tailscale status → yosemite-s1 ... active; direct 192.168.1.80
  • cached registry.json entry: via:"manual", no tailscale field, updatedAt = 9 days ago
What's actually wrongEvidence
Online = a stale cache, not live truth The label reads the cached tailscale.online field only. A live SSH probe runs (health.ts:207, 2.5s) — that's the "1% load" the snapshot showed — but it's display-only and never writes back. So a reachable box shows offline. That's the contradiction: "offline · 1% load / 16% mem."
Manual devices never get a tailscale field via:"manual" entries are added without tailscale.online, and refresh-mode sync skips nodes it doesn't already track (sync.ts:130). So they stay "offline forever" until a manual agents devices sync.
--host and --device are the same flag --device is a documented alias of --host (exec.ts:508). And --device(s) is also used for "config scope" in routines/monitors/apply/doctor — same word, two meanings.
No VPN-first transport, no key provisioning Tailscale is probe-only — it just supplies the .ts.net address + a liveness snapshot. All execution is raw SSH (ssh-exec.ts). No ssh-copy-id anywhere; auth.method:"key" assumes keys were authorized out-of-band.

Proposed: one connect(device) layer — VPN-first, keyed-SSH fallback, provision if missing

connection protocol — resolved once, used by every command
  • Reachability = live truth. Prefer the live probe over the cached flag; write the result back to the registry so "offline" is never a 9-day-old guess. Fixes the whole class, not just s1.
  • VPN-first. If the tailscale peer is up, go over the encrypted .ts.net path; else fall back to direct keyed SSH; else provision the key and retry — one ordered policy, at the resolver seam.
  • Real provisioning. agents devices add/provision runs an ssh-copy-id equivalent so auth.method:"key" is set up by the tool, not by hand.
  • Collapse the flags. One addressing flag (keep --device as the alias); rename the config-scope --device(s) collision to --on/--scope.
