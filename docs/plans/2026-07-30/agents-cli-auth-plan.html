01

Defect A — broker cache bypass causes unconditional Touch ID authorization

Mechanism: an ABI assumption invalidated by a build-system change, with a swallowed failure and a fallback that reaches the Keychain directly.

The secrets broker exists so that a bundle read is served from a cached, agent-held unlock rather than a Keychain access. Its three synchronous clients spawn an inline Node program:

// lib/secrets/agent.ts:799 · :849 · :893
spawnSync(process.execPath, ['-e', SYNC_GET_PROGRAM,  socketPath(), name, tokenPath()])
spawnSync(process.execPath, ['-e', SYNC_PING_PROGRAM, socketPath()])
spawnSync(process.execPath, ['-e', SYNC_LOCK_PROGRAM, socketPath(), name, tokenPath()])

process.execPath resolves to the Node executable only when the CLI runs as a Node script. Since 1.20.53 the macOS agents artifact is a Bun-compiled Mach-O executable, so process.execPath is the CLI itself and the invocation degenerates to agents -e …, which Commander rejects. Reproduced on this host:

$ agents -e 'console.log(1)'
error: unknown option '-e'

agentGetSync returns null on non-zero exit; agentReachableSync returns false; agentEvictSync no-ops. Each caller interprets those return values as “broker unavailable” and falls through to a direct Keychain read — which raises an authorization sheet. The daily policy's one-authorization-per-interval guarantee is therefore never in effect.

Class defect, not instance defect

A helper that resolves this correctly already exists — lib/cli-entry.ts:111-123 getCliLaunch(), which branches on isNodeScriptEntry(bin) and returns either {node, [script, …]} or {bin, […]}. The three broker clients were never migrated onto it. Remediating only these three call sites leaves the class open.

02

Defect B — unconditional fleet-auth probe on a wall-clock interval

Mechanism: a cache warmed on a metronome rather than on cache-miss, with no TTL in the auth path.

// lib/daemon.ts:649-650
setInterval(() => { void runFleetCacheWarm(); }, 3 * 60_000);
setTimeout (() => { void runFleetCacheWarm(); }, 60_000);

// each cycle: probeLocalFleetAuth() enumerates every installed (agent, version) on THIS host
// measured: rg -uu -c "fleet cache warm" …/daemon/logs.jsonl  →  3244

Each enumerated tuple performs a Keychain read and an authenticated HTTPS request. Two consequences follow, and they must be stated separately because they have different severities:

  • It multiplies Defect A. While the broker cache is bypassed, every probe cycle is a further set of direct Keychain accesses. Defect B is an amplifier of the Touch ID symptom, not its cause.
  • It does not, at present, rotate the token. This corrects an assertion made by one of my own investigations. usage.ts:920-922 returns { token: 'expired' } before reaching any refresh, per PR #1335, which is an ancestor of HEAD. Any analysis claiming the 3-minute timer is currently rotating credentials describes the pre-#1335 state.
Design defect beneath the bug

The warm loop was introduced to make agents devices list render instantly. That is a reasonable objective, but the implementation inverts the cost model: the probe cost is now paid unconditionally rather than on read. A cache should be refreshed on cache-miss by an arriving reader, governed by a TTL enforced inside the probe, so that no call site can bypass it. The usage cache has a TTL; the auth path has none.

03

Defect C — refresh-token rotation stampede

Mechanism: a single-use, server-rotating refresh token held concurrently by N processes across M hosts, with no mutual exclusion around the refresh operation.

Anthropic's OAuth refresh token is single-use: exchanging it invalidates it and issues a replacement. getClaudeAccessToken (usage.ts:1410-1433) exchanges whenever the access token is within the refresh leeway, then persists the result. It is reached from getClaudeUsageInfo at usage.ts:589 — i.e. from usage rendering and from agents run balanced rotation on every unpinned invocation.

The invariant that prevents this — refresh only from the single legitimate path — is presently maintained by convention, not by construction. There is no mutual exclusion: proper-lockfile is already a dependency (fs-atomic.ts:4) but usage.ts does not import it; lib/lock.ts is a manifest hasher, not a mutex; the only deduplication is an in-process Map (usage.ts:303) covering the background SWR path exclusively.

Why prior remediations amplified the fault

This section is the most operationally important in the document. Each item is a remediation that was actually applied and is documented degrading the system.

The controlling observation

The fleet auth-health monitor — 8c80c522, 9d5a8fe0, 893f80d9, 6e6b6a94 (2026-07-18) — was itself an agent's remediation for the logout fault. Three days later your own 1a4d5693 had to disable its refresh behavior, stating: “This was the dominant amplifier of the fleet-logout loop.” The diagnostic caused the condition it was built to diagnose.

Prohibited operations

  1. Do not execute or recommend claude setup-token. It mints a credential and rotates the shared refresh token. Prescribed 2026-06-24, 07-13, 07-20, 07-21; the failure rate increased monotonically across all four. One agent characterised it as “safe, additive… does not log out or invalidate your existing accounts” — directly contradicted by 1a4d5693.
  2. Do not execute agents apply with login: sync, --only …,login, or --copy-creds. fleet/remote-login.ts:4-6: “copying one OAuth credential file across N boxes is fatal — droid collapsed 10 boxes → 1 overnight.” Executed 2026-07-19 against win-mini (✓ push-login).
  3. Do not introduce any periodic process that refreshes a Claude token — health check, canary, ping, usage-bar warmer. A non-refreshing read is acceptable; an exchange is not.
  4. Do not widen the set of hosts holding this account until Defect C is remediated fleet-wide. On 2026-07-30 an agent set eight routines to --set yosemite-s0,yosemite-s1, adding two additional refreshers to the stampede.
  5. Do not remove and re-add an agent CLI as an auth remedy — it discards the credential it is intended to repair.
  6. Do not invoke an interactive login on a headless host — the OAuth URL was dispatched to xdg-open and opened in LibreOffice, leaving orphaned processes on yosemite-s0.
  7. agents fleet login cannot remediate Claude — CHANGELOG.md:88 classifies claude as non-remotable; only device-code flows (droid, codex, kimi) are drivable.
05

Remediation sequence

Ordered by blast-radius reduction per unit of risk. Each step lands independently and is independently revertible. No step mutates a credential.

1Capture a pre-change baseline

Required so that "worse" is measurable rather than anecdotal — the failure mode of every prior attempt. Record: per-day routine outcome distribution from ~/.agents/.history/runs/*/*/meta.json; the Keychain item inventory (73 items, metadata only); rg -c "Loaded Claude OAuth token"; and the current fleet-warm count (3,244).

2Merge PR #1457 — terminates Defect A

Restores the broker cache, which restores the daily policy's one-authorization-per-interval guarantee. This is the remediation for the Touch ID symptom. Then eliminate the class: migrate the three clients at lib/secrets/agent.ts:799 · :849 · :893 onto the existing getCliLaunch() (cli-entry.ts:111), and add a lint or unit test prohibiting bare process.execPath self-spawns.

3Merge PR #1449, then propagate to every host — terminates Defect C

Removes the token exchange from the usage/run hot path. Propagation is the step that determines success or failure: a partially-upgraded fleet still stampedes, because a single un-upgraded host continues to invalidate the upgraded ones. All four hosts running agents run against this account must be upgraded — zion, mac-mini, yosemite-s0, yosemite-s1.

4Establish mutual exclusion around refresh — makes Defect C structurally impossible

Route every refresh through one function guarded by a cross-process lock (proper-lockfile, already a dependency at fs-atomic.ts:4). Make saveClaudeOauth (usage.ts:1221-1248) atomic — it currently performs a read-modify-delete-write, so a losing racer can overwrite the winner's live credential with a dead one. Add a test asserting no call site outside that function invokes refreshClaudeToken.

5Convert the fleet-auth cache to read-triggered — terminates Defect B

Remove daemon.ts:649-650. Refresh on cache-miss by an arriving reader, with a TTL enforced inside probeLocalFleetAuth so no caller can bypass it. Separate "is this credential valid" (local, cheap, no network) from "is this agent reachable" (explicit, on demand) — they are currently conflated under one label.

6Restore failure detection

On 2026-06-24 an agent created an auth-canary routine and removed it 94 seconds later; it would have detected the July 17 cliff on the day it occurred rather than twelve days later. Reinstate a canary that reads without refreshing (mirroring the guard at usage.ts:920-922) and alerts out-of-band. Separately, add the missing failure branch at daemon.ts:315-321, where a null token read currently produces no log line — the reason this condition persisted undetected.

Explicitly out of scope

  • Reverting 1e910372. Removing a plaintext credential from the service manifest is correct.
  • The 62 orphaned Keychain items and the absent $HOME item. Real, but folding them in would confound measurement of whether the stampede remediation succeeded.
  • Any credential mutation whatsoever during diagnosis.

Verification protocol

Remediation efficacy is currently unestablished. This protocol is the acceptance gate.

  1. Defect A, direct: after #1457, execute a bundle read and assert the broker socket is contacted and no authorization sheet is raised. Then execute a second read within the policy interval and assert the same.
  2. Defect C, mechanism-level, before any code change: on one host, with an access token inside the refresh leeway, render a usage bar and observe whether the stored credential's expiresAt changes. This converts the rotation from inferred to observed.
  3. Defect C, post-change: repeat (2) on all four upgraded hosts and assert the stored credential is unchanged by a usage read.
  4. System-level, 48 h: zion's daily routine failure rate should return toward its pre-July-17 baseline of 11–33%, not 75–100%. mac-mini, at 93.6% failure, is the highest-signal host.
  5. Defect B: assert the fleet-warm counter stops advancing and that agents devices list still renders within an acceptable latency budget from a read-triggered refresh.
  6. Rollback discipline: one change at a time. If the failure rate degrades after any single change, revert that change before proceeding to the next.
