03 The monorepo seam

A company's monorepo hosts many projects, each a subdirectory — Rush CLI and Rush App live side by side under one checkout. So one Linear project maps to one subdir, and a project must store the monorepo root plus its subpath. The schema already carries this (root + defaultPath, and add --path <subdir> sets it), but membership resolution currently anchors on root alone — so two subprojects of one monorepo are indistinguishable. That's the load-bearing fix: resolve a session to the most specific matching path, so work in rush/apps/cli counts toward Rush CLI, not the parent.

The one decision for you: how far to formalize this in the tool.

A — Linear is the source of truth (recommended). Store the thin def (identity + repo/monorepo+subdir + linear.projectId); pull goal/objective/milestone/drift live onto the card. Nothing to keep in sync by hand.

B — also declare goals/milestones locally in YAML. Projects carry their own objective + milestone list even without Linear. More self-contained, but a second copy that drifts from Linear.
