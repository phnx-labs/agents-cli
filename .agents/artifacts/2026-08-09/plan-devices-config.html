One `agents devices config` surface, persisted in synced ~/.agents/agents.yaml

Device configuration is scattered across set/configure/note/set-interactive plus enable/disable/prefer/unprefer, and the per-device doc sync is silently broken on the real fleet (devices/ is gitignored after the pin-churn incident). This plan consolidates everything into one key-value command with an interactive settings menu, stored in central ~/.agents/agents.yaml fleet.devices.<name>.config — the proven synced path, so selections back up with agents repo push/pull. Old commands become hidden tombstones.

Purpose

Four-plus command shapes (set, configure, note, set-interactive, enable/disable/prefer/unprefer) edit three different stores, two of which never leave the machine. One menu, one synced home.

The TTY settings menu

$ agents devices config release-host
❯ agents.max-concurrent   4         max parallel agents Factory may place here
  scheduler.enabled       on        routines scheduler on this device
  auto-launch.enabled     on        Factory may auto-pick this device
  auto-launch.preferred   off       boost in auto-launch ranking
  ssh.auth                key       key | password (+ bundle / identity-file)
  notes                   1 note    free-form operator notes
  interactive.host        —         make this the device that shows YOU artifacts
No auto-push is added: per-device snapshot churn into the shared repo is what caused the original `devices/` gitignore incident. Config writes are user-initiated and ride the existing `agents repo push/pull` + `agents sync` flow — which is exactly the backup path the user asked for.

Public Interface

agents devices config release-host                            # TTY menu; --json for machine callers
agents devices config release-host agents.max-concurrent 4    # set (validated)
agents devices config release-host scheduler.enabled off
agents devices config release-host ssh.auth password          # then: ssh.bundle Owner
agents devices config release-host notes "runs the releases — don't reboot"
agents devices config release-host ssh.identity-file --unset

# ~/.agents/agents.yaml (synced, backed up)
fleet:
  devices:
    release-host:
      config:
        maxAgents: 4
        schedulerEnabled: false
        autoLaunch: { enabled: true, preferred: true }
        ssh: { user: Owner, auth: password, bundle: Owner }
        notes: ["runs the releases — don't reboot"]
