Current architecture — how planning is delivered today

Behavior reaches agents through four channels. Built-in plan mode (the --mode plan / /plan / Shift+Tab toggle) sits outside these — it constrains tools and requires ExitPlanMode, but injects no methodology, so it relies entirely on whatever the loaded rule text says. Of the four content channels, only two reach all five harnesses; the rich /plan custom command is the top-right row that degrades and, on claude, may not even fire (shadowed by the built-in /plan). That is why codex and kimi got nothing.

Grounding (file:line): the hook matches only ExitPlanMode/exit_plan_mode (plan-html-reminder.sh:34-46); plan mode injects no instruction text per harness (apps/cli/src/lib/exec.ts:457-650); the methodology lives in commands/plan.md (Step 1 restate :20, panel :181-230, API-required :140-149).

Does artifacts-cli need upgrading? Yes — two additions

You asked me to check. The plan template today scaffolds only Purpose / Proposed Changes / Public Interface / Validation / Risks / Tracking (templates.js:52); the validator has no excerpt or checklist awareness, and the renderer ships no syntax highlighter and blocks inline style (must use artifact-* classes). So two first-class additions are needed, each in the artifacts-cli repo (its own PR + release):

Addition What it does Renders today without it?
code-diff component GitHub-style file-diff viewer: collapsible per file, +N −N badge, line-number gutters, red/green add-remove coloring, syntax highlighting No — a fenced diff block is monochrome (no highlighter), and fenced code inside <details> doesn't render at all (verified)

The code-diff component is a prerequisite for the diff look — it cannot be faked in Markdown, so it gates on the artifacts-cli release. The checklist can ship immediately as - [ ] lists (the component upgrades the look later).
