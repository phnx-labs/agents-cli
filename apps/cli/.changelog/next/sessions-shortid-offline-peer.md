- **A short session id resolves even when a fleet peer is offline.** `agents sessions preview <shortid>`, `agents resume <shortid>`, and every other id-shaped selector previously refused to resolve whenever any registered device failed to answer the fan-out — printing `Partial session resolution: <peers> did not answer` and rendering nothing, even though exactly one session on the reachable fleet matched. A session id is a UUID, so a short id is a UUID prefix and is unique by construction: an unreachable peer cannot be hiding a second session that shares it. One hit on the reachable fleet now resolves. Only a **label** selector stays fail-closed, because a distinct session may genuinely carry the same label on an offline box, and an id-shaped selector that matched nothing reachable still reports `partial` — there the offline peer really can hold the answer. Source: `apps/cli/src/commands/sessions.ts` (`metadataResolveOutcome`, `renderSessionPreview`).
