## `agents activity`

Recent agent activity across the fleet -- plans, PRs, worktrees, sub-agents, by project

- Usage: `agents activity [options]`
- Flavors:
  - `agents activity                              # the whole fleet, by project`
  - `agents activity --local                      # just this machine`
  - `agents activity --flat                       # one newest-first stream`
  - `agents activity --host worker-s1           # one box over SSH`
- Flags:
  - `--all` — Include routine activity (file edits) inline, not collapsed
  - `--milestones` — Only milestone events (plans, PRs, worktrees, sub-agents)
  - `-n, --limit <n>` — Cap the milestones shown (routine work rides along as counts); with --all, caps every event (default: 40)
  - `--since <minutes>` — Only events within the last N minutes
  - `--local` — Only this machine -- skip the cross-machine SSH fan-out
  - `-H, --host <target...>` — Scope to remote machine(s) over SSH; repeatable
  - `--device <target...>` — Alias for --host; repeatable
  - `--devices-all` — Fan out to every reachable device (the default; kept for scripts)
  - `--hosts-all` — Alias for --devices-all
  - `--group-by <field>` — Bucket the stream by project | device | agent | none (default: project)
  - `--flat` — One newest-first stream instead of project buckets
  - `--project <name>` — Only items under one project; exact match on the resolved (defined-project-first) label
  - `--filter <text>` — Narrow to items matching a project / device / agent / event / ticket
  - `-h, --help` — Show help

  - `agents add claude@oldest`

- Flags:
  - `--isolated` — Install a fully self-contained copy that never touches your existing ~/.<agent> or default. Launch it explicitly with `agents run <agent>@<version>`. Cannot be combined with --project.
  - `-y, --yes` — Auto-accept defaults without prompting (useful for scripts and CI)

## `agents apply`

Reconcile the fleet to a declared profile: install agents, sync config, propagate login.

- Usage: `agents apply [options]`
- Flavors:
  - `agents apply --plan -f agents.yaml`
  - `ag apply -f agents.yaml`
  - `agents apply --device worker-s1 -y`
  - `agents apply --agent claude@all --device worker-s0 -y`
- Flags:
  - `--plan` — Show the reconcile plan and exit (no changes)
  - `--dry-run` — Alias for --plan
  - `-y, --yes` — Skip the confirmation prompt
  - `--device <name>` — Scope the apply to a single device
  - `--agent <specs...>` — Override the roster for targeted device(s): install these specs instead of the manifest's. Use `claude@all` to replicate every version installed on this machine.
  - `--only <dims>` — Limit to dimensions: comma list of agents,config,login
  - `--no-login` — Do not propagate logins
  - `-h, --help` — Show help

Without a value the terminal is detected from your live sessions (`agents sessions --active` host), so it lands where you already work — Ghostty for a Ghostty user, iTerm for an iTerm user.   - `--timeout <duration>` — Kill the agent after this duration (e.g., 30m, 1h, 2h30m)
  - `--fallback <agents>` — Comma-separated agents to try on rate-limit failure. Each entry accepts an optional @version pin (e.g., codex@0.116.0,antigravity). The primary runs first; if it exits with a rate-limit error, the next agent picks up via /continue handoff.
