01“De-escalation” was the wrong word

I did not mean “lower the completion standard” or “let the agent give up.” I meant: stop issuing the same instruction once it is no longer adding information, then prompt a strategy change.

de-escalation→loop-breaker guidance The proof bar stays fixed. The tactic changes: retry differently, inspect the live blocker, coordinate ownership, switch to another useful track, or escalate a genuinely human-only step.

verdict The hook is useful as a persistence backstop: work usually moved and the cited PRs usually terminated. Its efficiency falls as repetition rises, and this observational dataset cannot prove the hook caused the eventual merges.

What looks effective

Agents usually act. After deduplicating simultaneous hook copies, no repeated interval was a pure restatement. Four in five contained a change, verification, or coordination action.

Outcomes usually terminate. Live GitHub checks found 112 merged, 5 deliberately closed, and 5 still open among 122 unique cited PRs.

What looks weak

Open-PR guidance repeats. Only 83 of 150 open-PR chains cleared after the first attempt. Of 33 reaching a third attempt, 21 continued.

Late repetitions add less. First-attempt clearance was 68.7%; second-attempt clearance among remaining chains was 53.9%; third-attempt clearance was 37.1%.

05The shipped loop-breaker has not been tested by real exposure yet

current answerThe new behavior is not yet measurable. It has seen zero real third-repeat exposures since merge. Calling it effective or ineffective now would be invented.

06What is expected to be accomplished now

  1. Fix the measurement unit.Ensure one installed hook instance emits one intervention. Deduplicate near-simultaneous feedback defensively.
  2. Key repetition to the active goal.Reset on a genuine user turn or use the reconstructed task/checklist identity. A transcript-wide string count is not a task state.
  3. Keep the prompt agentic.Show the missing evidence and offer ideas, including retrying differently, inspecting live state, self-unblocking, parallelizing bounded work, coordinating a live owner, or escalating a human-only step. Let the agent choose.
  4. Instrument outcomes.Record gate, goal key, logical attempt number, hook version, next action category, terminal result, and time to terminal state. Do not infer these later from prose when the hook can emit them directly.
  5. Evaluate after exposure.Compare post-fix third-attempt chains with the pre-fix baseline: continuation after third, action diversity, time to terminal state, and terminal outcome rate.

Success means

No duplicate feedback. “Third” refers to the same unresolved goal. Repeated guidance changes the available tactic or names the live blocker. The current 95.9% observed terminal-PR rate does not regress.

It does not mean

More rigid branches, permission-seeking, or lowering the proof standard. The hook should provide state and useful options; the agent remains responsible for choosing and carrying out the next move.
