Show the configured model wherever agents displays an agent

Every place we already surface an agent+version — agents view, the agent@version detail, use, add, status, inspect — should tell the user which model that agent is set to use right now, with a short label saying where the selection comes from. Usage/limit windows already look good and stay exactly as they are.

01The gap today

A user inspecting an agent sees version, account, and usage windows — but the model is effectively invisible. The only model hint is a gray run model:<x> suffix on agents view rows, and it appears only if the user manually set an agents.yaml run.defaults entry (view.ts:621-651). The agent@version detail view shows no model at all (view.ts:1026-1049). Yet the agent always runs with some model — its native settings.json model, or the CLI's built-in default.

Outcome the user wants

"The user is trying to see what an agent has." One glance answers what model is this agent+version set to, and why.

02What it will look like

Design principle

The model gets the same treatment and priority as the version — it sits right next to it, everywhere, and is never its own row or label. Wherever a version shows, the model shows beside it: agent · version · model · account. The source (run default / config / cli default) is resolved but kept out of the human views — it's available in agents view --json. Usage windows are untouched.

03One shared resolver

Add resolveConfiguredModel(agent, version) to apps/cli/src/lib/models.ts, beside the existing resolveEffectiveModel and getModelCatalog. Every surface calls this one function, so the display can never drift between commands.

export type ConfiguredModelSource = 'run-default' | 'config' | 'cli-default';

export interface ConfiguredModel { model: string; source: ConfiguredModelSource; }

export function resolveConfiguredModel(agent, version): ConfiguredModel | null {
  // 1 · run default — resolveRunDefaults(agent, version).model      (lib/run-defaults.ts)
  // 2 · config      — read getVersionHomePath()/agentConfigDirName()/settings.json ."model"
  // 3 · cli default — resolveEffectiveModel(agent, version)          (catalog isDefault)
}

Honest layering, not a fallback band-aid

Each layer is a real, distinct source the agent genuinely consults. The config read is best-effort (Claude's settings.json has a top-level "model"; agents without one fall through). A missing/malformed file is a fall-through, not a swallowed error. Returns null only when the agent isn't model-capable. Callers holding 'default' resolve a concrete version first via resolveVersion().

Two sibling formatters keep every surface consistent:

  • formatAgentIdentity(agent, ver, {model, account}) → the cluster Claude@2.1.186 · opus · you@rush.dev, reused by the view detail header and the use / add / status confirmations.
  • formatModelSource(source) → run default / config / cli default, emitted only in agents view --json (configuredModel.source).

The bare model id (opus) comes straight off resolveConfiguredModel(...).model and is placed beside the version; the source word never appears in a human view.
