- **`agents view` shows Claude usage again — the fleet auth-health probe no longer hammers `/oauth/usage` into a permanent 429 (RUSH-2998).** Usage-refresh was already deduped to one primary host (#2606), but the auth-health probe (`probeLocalFleetAuth` → `probeClaudeStatus`) hit the same `/api/oauth/usage` endpoint on **every** device every 3 minutes. Across the fleet that multiplied one per-account request quota until the endpoint returned `429` for every Claude account; the shared `Retry-After` backoff then parked usage fleet-wide, and the usage cache froze (windows stale-zeroed → `agents view` rendered `S: 0% (now) W: 0% (now)` for weeks). The auth-health live probe now follows the same publisher/subscriber split as usage-refresh: only the usage-primary host (`usage.primary-host`, else `interactive.host`) fires the network probe; a subscriber reports the local credential verdict (`unverified` when present) instead, and its throttle state still arrives via the primary's replicated usage cache. Rotation is unaffected — it gates on the fleet-replicated usage snapshot and fails open on any non-`revoked` auth verdict. Source: `apps/cli/src/lib/auth-health.ts` (`probeAuthHealth`/`probeLocalFleetAuth` `liveProbe` gate), `apps/cli/src/lib/daemon-ticks.ts` (`refreshLocalFleetAuthState` role resolution).
