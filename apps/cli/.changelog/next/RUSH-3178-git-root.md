- **`scripts/test.sh --device` no longer resolves paths against an unrelated git repo.** The suite ships to the worker without `.git` (for the attestation producer's isolated worktree that file is only a `gitdir:` pointer into the origin machine's object store), and with no `.git` marker `git rev-parse --show-toplevel` walked *up* out of the shipped tree to the first ancestor repo it found — on a worker that is `~/.agents`, the DotAgents repo. Every git-rooted path then resolved against the wrong repository: `release-manifest.test.ts` went looking for `~/.agents/native/computer-mac/Sources` and four tests failed with a confusing "helper input missing", which reads like a Linux/macOS difference rather than the path bug it is. The shipped tree is now given an empty repo so the walk stops there. Source: `apps/cli/scripts/test.sh`. The shipped tree now gets a blank repo with a real initial commit, matching what `sandbox.sh`'s crabbox path has always done for the same reason ("blank git for tests that need one"); the commit identity is supplied with `git -c` rather than written to the worker's config, because a worker typically has no git identity and without one the commit fails silently into an unborn `HEAD`.
