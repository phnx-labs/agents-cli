Purpose

agents sessions focus currently builds a separate live-only target map. A tmux session retained with remain-on-exit can therefore be selected even when the process inside its pane has ended. The command successfully reaches the device and attaches tmux, but the user lands on stale terminal content followed by Pane is dead.

The corrected surface treats selection and action as separate concerns:

  • the existing sessions query/filter engine decides which sessions appear;
  • the existing preview explains the selected session;
  • a fresh liveness check decides whether Enter attaches or recovers;
  • recovery preserves the original isolated version when usable, otherwise a healthy version of the same harness loads the indexed transcript through /continue.

Proposed Changes

Selection contract

Create one reusable selection model for the sessions command and focus:

Input Resolution
14567b8a Unique ID/prefix; focus directly after applying explicit filters
claude All recent Claude sessions; always show the picker
claude@2.1.187 Recorded origin version, including historical uninstalled versions
claude@latest Resolve latest independently on each queried device
Other text Existing topic/path/session search

The shared model carries agent/version selectors, device/host/local scope, project/time/team/resource filters, favorites, and the complete live-status union (active, working, idle, waiting, orphan, crashed, closed, abandoned, queued, unknown). Render-only flags remain outside focus.

Recovery contract

After selection, probe the target process and tmux pane again to close discovery/action races. A living pane always wins, even if the installed-version inventory changed after launch. A dead or missing pane never attaches.

For recovery, resolve the indexed SessionMeta on the target device. Native resume is allowed only when the recorded origin version is installed, signed in, healthy, and still owns the transcript home. Otherwise the existing balanced resolver selects a healthy version of the same harness, starts a fresh interactive session on the same device, and sends /continue <old-session-id>. The continue skill reads through the session index, including soft-deleted version homes.

Public Interface

agents sessions focus 14567b8a
agents sessions focus claude@latest --device yosemite-s0
agents sessions focus claude --active
agents sessions focus claude --orphan --device yosemite-s0
agents sessions focus codex@latest --closed --since 7d
agents sessions focus --orphan --waiting

Agent/version and text selectors always show the picker, even for one result. With no selector or filters, focus preserves its current active-session default. Multiple status flags form a union. --attach-only remains a strict no-recovery mode.

Risks

Risk Mitigation
Discovery says live, process exits before Enter Re-probe process and pane_dead immediately before the action
Local latest differs from remote latest Resolve selectors on each device that owns the candidate rows
Cross-version native resume cannot see the old transcript Use indexed /continue; never native-resume from another isolated home
Status-filter behavior drifts again One shared selection type, normalization function, and parity tests
A healthy replacement cannot be selected Fail with device, origin version, and inventory/health reasons
Load-bearing rule: a tmux target proves that a pane was retained, not that its process is alive. Focus must probe liveness before attaching.
