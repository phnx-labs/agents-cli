Store routine activation in each device's agents.yaml

Move mutable routine activation out of definition YAML. Each device records enabled routine names in its own synced agents.yaml; definitions remain layered resources and run history remains under .history.

Built-in Watchdog definition moves to the system routines repository.·Presence in a device document means enabled on that device.·Each device writes only its own configuration document.

Purpose

Routine definitions currently mix executable configuration with mutable enabled and devices state. Enabling a built-in routine therefore creates or rewrites a user-layer copy of a system definition. The new model keeps definitions immutable and stores device activation beside the rest of that device's configuration.

Load-bearing boundary: definition YAML describes what a routine does; a device document alone decides whether that device runs it.

Proposed Changes

Area Change
Device metadata Add an in-memory deviceRoutines list that serializes as top-level routines: only in devices/&lt;hostname&gt;/agents.yaml.
Routine resolver Resolve definitions with existing precedence, then schedule only names present in the current device document.
Watchdog Ship watchdog.yml in the system repository; retain the deterministic CLI runner invoked by agents watchdog --nudge.
Setup Add agents setup watchdog; selected devices perform their own activation write and daemon reload.
Migration Each upgraded host materializes its effective legacy state into its own device document without rewriting definitions.
Runtime data Keep run timestamps, status, reports, and logs in the existing .history/runs tree; no new database.

Public Interface

agents watchdog on
agents watchdog off
agents watchdog status
agents routines resume <name>
agents routines pause <name>
  • agents watchdog on and agents watchdog off change Watchdog membership on the current device.
  • agents watchdog status reports local activation and devices whose synced configuration enables Watchdog.
  • agents routines resume/pause add or remove membership on the current device.
  • agents routines devices reads activation across device documents; mutations execute on the target host so each hostname remains single-writer.
  • Routine list JSON adds enabledDevices and runsHere while retaining local last-run fields.

Validation

  1. Verify routine activation round-trips only through the current device document.
  2. Verify the daemon does not schedule a definition absent from routines:.
  3. Verify the same routine may execute independently on two activated devices.
  4. Verify setup, Watchdog sugar, migration, daemon reload, and unavailable-device reporting.
  5. Run the real daemon with isolated homes and confirm a Watchdog tick changes history without modifying definitions or activation.
  6. Run bun run test:remote, the canonical build, and an installed-CLI smoke flow.

Risks

[!WARNING] A control machine must not edit another hostname's device document. Remote activation is performed by the target device's CLI; an unavailable device is reported as unchanged.

  • Legacy unpinned routines ran once per device. Migration therefore executes locally on every upgraded host.
  • Malformed activation data is inert and produces a file-specific error; it never enables all routines.
  • System definitions and CLI behavior ship in coordinated PRs so setup never references a missing definition.
