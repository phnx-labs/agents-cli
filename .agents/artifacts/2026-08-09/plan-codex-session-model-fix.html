Purpose

Make agents sessions display the correct model for Codex agent sessions. Currently the model column is blank for Codex because the session scanner ignores the turn_context events where Codex now writes per-turn metadata.

Codex rollouts put the model name in turn_context.payload.model, not session_meta.payload.model. The scanner must read both.

Current State

For Claude sessions, agents sessions shows the model (e.g., opus-4-8). For Codex sessions the model column is hidden or shows -. Real Codex rollout files look like this:

{"type":"session_meta", "payload":{"id":"sess-1","cwd":"/repo","cli_version":"0.9.0"}}
{"type":"turn_context", "payload":{"model":"gpt-5.6-sol","cwd":"/repo"}}

The existing scanner (applyCodexLine in discover.ts) handles session_meta, response_item, and event_msg, but explicitly skips turn_context. So state.model stays undefined and the UI treats the session as having no model metadata.

Risks

  • Per-turn model changes: turn_context carries per-turn metadata. If Codex ever swaps models mid-session, the first model seen wins. This matches the existing session_meta behavior and is acceptable for a session-list display.
