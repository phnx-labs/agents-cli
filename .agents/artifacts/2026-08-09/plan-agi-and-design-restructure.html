Restructure: an `agi` plugin for the CLI surface, and one design front door

The system repo scatters the agents-CLI capability skills (browser, computer, run, sessions, teams, secrets, devices, monitors, routines, cloud) loose at the top level, and ships three competing "design" front doors. This maps the current landscape and proposes two clean plugins — `agi` (the CLI surface) and a consolidated `design` — plus the one CLI feature the move depends on: skill aliases.

Purpose

Two problems, one theme — the capability surface is not organized the way a user (or an agent under token pressure) reasons about it.

1. The agents-CLI capabilities are loose top-level skills. browser, computer, run, sessions, teams, secrets, devices, monitors, routines, cloud are all features of one product — the agents CLI (a.k.a. AGI CLI) — but they sit as unrelated top-level skills next to authoring tools like mq and plan-render. Nothing says "these are all one thing." The meta skill that describes the CLI is itself named agents-cli and is a loose skill, not a plugin.

2. Design has three front doors. design:design (the new keyless/offline plugin), ~/.agents/skills/design (the old flat skill), and create:design (in the user create plugin) all answer "design something." Two of them carry value the canonical plugin lacks (an anticipate mode, an anti-tells catalog), and the canonical one ships hardcoded example files we now want replaced with live web-inspiration browsing.

The linchpin: there is no skill/command alias in the CLI today — alias exists only for extra repos (rush:*). The moment browser moves under an agi plugin it is invoked agi:browser, and every bare browser reference (rules, muscle memory, other skills) breaks. So the alias/shortcut feature is a hard prerequisite of the move, and it is an agents-cli code change, not a .system edit.

Proposed Changes

The shape: two clean plugins + one CLI feature

1 · New agi plugin (the CLI surface)

Rename the agents-cli skill to agents and make it the flagship of a new plugins/agi/. Move the loose CLI-feature skills under it so they read as one product:

Moves under agi/ Invocation today After
agents-cli (renamed agents) agents-cli agi:agents (alias: agents)
browser browser agi:browser (alias: browser)
computer computer agi:computer (alias: computer)
run, teams, sessions, cloud bare agi:run / agi:teams / agi:sessions / agi:cloud
secrets, devices, monitors, routines bare agi:secrets / agi:devices / agi:monitors / agi:routines

Stays top-level (not a CLI verb — a separate tool or authoring surface): artifacts, plan-render, visualize, mq, tickets, docs, learn. (Confirm — decision D3.)

2 · Skill-alias / shortcut support (agents-cli code)

A new resource capability: a skill (or command) declares a short alias so it stays reachable by its old bare name after moving into a plugin namespace. Sketch:

# plugins/agi/skills/browser/SKILL.md frontmatter
name: browser
plugin: agi          # invoked agi:browser
aliases: [browser]   # bare `browser` and `/browser` still resolve here

The resolver (apps/cli/src/lib/resources.ts / skills.ts) gains alias-aware lookup, and the model-facing skill listing shows the canonical name with its alias. This is what makes the whole move non-breaking. It ships on the agents-cli release train (merge-only for us; the train publishes).

3 · One design front door

Fold the unique value into plugins/design, then retire the other two doors:

Fold in From Into
anticipate mode (flow dead-ends) old skills/design + create:design new mode anticipate.md
anti-tells catalog (era-specific AI tells) create:design/design-anti-tells.md a design-core section (always-on)
brand (BRAND.md) spec detail create:design/brand-md-spec.md system mode (or own brand mode — D-brand)
web-inspiration browsing (your ask) — new design-core: use the browser skill to screenshot real sites and eyedrop palette/type/layout
hardcoded examples/ (airbnb, intercom, rush) old skills/design removed — replaced by live browsing

Then ~/.agents/skills/design and create:design are retired (full delete, redirect stub, or left alone — decision D4).

4 · Update the rules/subrules that point at the old names

These reference the tool skills and must move to the alias/agi: names:

Subrule What references it
rules/subrules/tech-stack.md the "Right tool for the job" table (browser, pty, teams, secrets, mq, tickets)
rules/subrules/foundations.md F2 ladder ("the browser skill", "agents computer")
rules/subrules/remote-fleet-dispatch.md devices / hosts
plan-presentation/*, truly-agentic-git-workflow/pr-description-reminder.sh browser/pty capture references

Public Interface

  • New invocations: agi:agents, agi:browser, agi:computer, agi:run, agi:sessions, agi:teams, agi:secrets, agi:devices, agi:monitors, agi:routines, agi:cloud — each with a bare alias preserving today's name.
  • Design: design:design gains anticipate; design-core gains anti-tells + a web-inspiration step; examples/ removed. design/create:design cease to be doors.
  • CLI: skills/commands may declare aliases: [...] in frontmatter (new).
